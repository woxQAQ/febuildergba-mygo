# 本地真实 ROM 验收记录

此前使用 `febuildergba-go/.rom/` 中的两份真实改版 ROM 完成下列文件与 UI 检查，所有修改和模拟器运行均使用临时副本。原件的 SHA-256 在验证前后保持一致；ROM 和运行产物不进入 Git。

后续已加入 FE8U 原版，完成三份样本的[章节内修改效果验收](rom-chapter-acceptance.md)：人物 HP／力量、职业 HP、武器威力在属性页及实际战斗中生效；人物表等级未改变开场部署等级，原因和边界见该记录。

按用户要求，Go 项目的全部 `_test.go`、合成 ROM 生成器和测试辅助代码已移除。下列内容保留已执行的结果，不表示仓库仍维护对应自动测试入口。后续使用真实 ROM 副本、实际交互、构建及静态分析推进验收。

## 窄字库与图像预览

名称映射来自固定旧版基线的 `NarrowFont/MenuLowercase`、`MenuUppercase` 安装定义。逐个读取 ROM 菜单字库实际指向的字形，核对单字节结构与 64 字节位图摘要后启用对应字符，共有 44 个已知窄字库槽位。没有依靠 ROM 文件名或某一名称猜测字符，也没有把旧版字体资源打包进新版。

素材列按各表中的资源 ID 去重，头像跳过空引用 ID 0，图标 ID 0 为有效数据。上述引用全部成功解码；已经检查 Storch、Rena、Ironclad 职业卡及铁剑图标的实际 PNG 输出。

预览已接入人物、职业和道具编辑页，支持整数倍像素缩放。素材引用由字段定义提供，预览和原始数据入口共用一套 UI；文档修订或素材 ID 改变后重新读取。展开原始数据可进入头像记录、图标字节及调色板，损坏图像不关闭其他字段编辑。

实现支持有输出上限的 GBA LZ77、4bpp 图块、BGR555 调色板、普通头像拼接、职业卡和已知 MUG_EXCEED 图块扩展。HALFBODY 半身像格式已按旧版规则接入，但这两份样本没有覆盖该格式，不计为实际通过。图像导入、动画播放、字库修改及其他自定义字体仍未完成。

素材接入时没有新增单测或保留检查脚本；当时的原生启动记录为携带两份临时 ROM 副本运行 6 秒未提前退出。后续原生截图及编辑操作记录见下文；素材缩放操作和输入法仍需桌面验收。

### 紧凑编辑器的原生窗口检查

职业能力已改成基础／成长率／上限／转职加成矩阵，人物使用个人加值／成长率。没有对应字段的组合显示 `—`；其他属性采用同行布局。数值右对齐，原先每字段的常驻加减按钮集中在底部当前字段栏；原始地址和字节编辑入口也随当前字段显示。

使用项目外的临时 Go overlay 启动实际 MyGo 原生窗口，通过应用的 CapturePage 获取图像。两份 ROM 各检查职业浅色、880×560 英文窗口、职业深色英文、职业原始数据、人物和道具视图，另记录无效草稿及保存状态。已审阅宽窗口中能力与武器熟练度并排、窄窗口换行，以及中英文表头和短数值的显示。

向应用自身发送 AppKit 键鼠事件，观察以下行为：

- 聚焦职业基础 HP 后，方向上键增加 1；Cmd+Z 恢复原值，Cmd+Shift+Z 重做。
- Tab 将焦点移到同一能力的成长率。Cmd+A 后输入单独的 `-`，输入框保留草稿并提示范围，ROM 中的成长率不变。
- 方向上键从已提交值增加成长率，撤销后恢复；底部加号可增加当前 HP，撤销恢复。
- Cmd+S 保存成功，文档回到已保存状态。完整文件比对只发现下列指定 HP 字节变化；备份与源文件完全相同。

## mGBA 结果

使用 `/Applications/mGBA.app/Contents/MacOS/mGBA`，版本 `0.10.5`。分别启动编辑后副本，通过其 GDB stub 继续执行 8 秒后暂停，读取 ROM、CPU 和显存状态。

| 项目 | Vision Quest | Dream of Five |
| --- | --- | --- |
| 人物等级，GBA 地址 `0x08803D6F` | `2`，原值 `1` | `3`，原值 `2` |
| 职业基础 HP，GBA 地址 `0x0880716F` | `19`，原值 `18` | `33`，原值 `32` |
| 暂停时 PC | `0x00000188` | `0x03002F84` |
| 显存首 256 字节中的非零字节数 | 255 | 256 |
| 上述显存片段 CRC32 | `1E33DB47` | `5B8E5225` |

这证明 mGBA 读取了修改后的内容，并观察到 CPU 和视频内存活动；当时尚未进入章节。后续已完成 FE8U 原版及这两个改版的属性、攻击预览与实际战斗对照，详见[章节验收](rom-chapter-acceptance.md)。其中人物表等级字节的变化没有改变开场部署等级，不能将本表的读取结果视为等级生效。PC 和显存数值是当时观察值，不作为后续执行必须相等的断言。

两个模拟器进程均由本轮启动并在检查后停止。Qt 输出过 backing-store 缩放提示及 macOS `IMKCFRunLoopWakeUpReliable` 日志，尚未确认这些日志是否影响实际输入法交互。

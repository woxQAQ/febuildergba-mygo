# 斗技场原生规则

旧版入口为固定基线的 `ArenaClassForm.cs`、`ArenaEnemyWeaponForm.cs`、`LinkArenaDenyUnitForm.cs`。消费者依据见[核对来源](../sources.md#斗技场规则)，版本及功能状态见[覆盖矩阵](../coverage.md#斗技场规则)，操作见[使用指南](../user-guide.md#斗技场)。

## 对手职业

三组列表分别用于玩家持剑／枪／斧、弓、魔法武器时的对手抽取。列表是非零职业 ID 字节序列，以一个零字节结束；原生地址不要求四字节对齐。重复项保留，参与抽取权重，不按职业去重。

游戏读取玩家人物与职业的属性并取 `0x100` 上级职业位，再统计列表中同一层级的职业数，随机选取其中一项。第二次查找没有结束项保护，因此修改后的列表必须引用当前职业表中的有效非零 ID，并至少包含一个上级和一个下级职业。这里按当前职业布局的属性判断，不按名称或职业编号猜测层级。编辑器将有界读取及编辑限制为最多 256 个非结束项；这是编辑器的读取上限，不是游戏原生容量。

替换、添加、复制、删除和排序都先进入草稿；零结束项由草稿保留。写入追加当前选定列表，只更新其已确认入口，原来共享起点或指向列表内部的其他组保持原引用。结束项之后的未知数据留在原位置，不视作可回收空间。

## 基础武器与升级查找

基础武器为固定 8 字节，顺序为剑、枪、斧、弓、杖、理、光、暗。双方都从该表取得初始武器。杖槽保留，不通过普通字段修改；其余槽可选择当前道具表中的非零 ID。应选择对应类型、可用的 E 级武器；编辑器不模拟武器使用条件、属性锁或实际战斗。

FE7／FE8 的初始生成与无法使用当前武器时的兜底逻辑分别读取同一表。两个已确认消费者指向不同目标时，报告 `game.arena_reference_conflict`，不自动合并或只修改其中一处。FE6 只有本流程确认的初始生成消费者。

升级函数将固定 26 字节复制到栈，再逐字节查找当前道具 ID。首个匹配项决定结果：后一字节非零时用它生成新武器，为零时保留原武器；`FF` 结束整个扫描。未匹配的原生返回行为没有可靠结果，因此基础武器和升级表共用草稿，预览要求每种非杖基础武器能在首个 `FF` 之前匹配，最后一组在 `FF` 前有零分隔。

普通编辑只替换首个 `FF` 前既有非零、非 `FF` 的道具项，保留零分隔、结束标记、表序及固定容量，不增删。首个 `FF` 后的缓冲区字节仍随完整 26 字节原样复制。新值须存在于当前道具表，升级项不允许 `FF`。未改动的未知值保留；不据此认定其游戏行为有效。

## FE8 联机参战限制

原生函数固定读取 **11 个有符号半字，共 22 字节**，与人物的单字节 ID 比较。它不按零结束，也不只比较每项低字节。普通字段允许选择当前人物表中的非零 ID 或写零以清空一个槽；不增删槽位。零之后的槽仍参与判断，重复项、已有宽值及负数的原始半字在未明确替换时保留。第 12 项及之后的字节不属于这个读取范围，原地保留。

FE6／FE7 的固定旧版配置没有对应入口，页面不提供此组。这个名单与章节斗技场的对手职业、武器规则独立。

`game/arena` 提供资源声明、草稿及不可变计划；`game/arena_sources.go` 提供当前记录布局和会话保护。每个职业列表、武器组和联机名单独立读取。一个组损坏不阻止其他有效组，基础武器与升级表则必须同时可读。

预览列出逐行变化、将更新的消费者及重叠的其他斗技场资源。修改的载荷追加到 ROM 末尾，所选入口、载荷和文件长度一次提交、撤销和重做；未选定独立引用及原字节保持不变。不扫描形似指针的字节来补齐自定义消费者。

全部已知指针及有界可读载荷加入会话 Claim，包括消费者分离时分别能读取的载荷。跨文档、修订或有效布局变化使草稿和计划失效；指针被其他资源占用、非法目标、长度或 32 MiB 容量冲突都不留下部分写入。修改过或含非法输入的 UI 草稿跨组保留，失效后只能明确放弃并重读；数值草稿使用输入框自己的文本撤销。

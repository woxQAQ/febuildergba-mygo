## 道具字段预设

`game/records/items.go` 的 `ItemChoices` 提供具体字段的原生值，不提供通用元数据解释器。类型 `0–7` 依次为剑、枪、斧、弓、杖、理、光、暗，`9` 为道具；其他分类保留原值。所需武器等级使用当前版本声明的 EXP 门槛：FE6 的 E/D/C/B/A/S 为 `1/51/101/151/201/251`，FE7／FE8 为 `1/31/71/121/181/251`，`0` 表示无等级要求。非门槛值不按近似等级归一化。

射程高半字节为最小距离、低半字节为最大距离，预设提供 `11/12/13/22/23/3A/3F` 的固定范围，`00` 为无射程，`10` 为随魔力变化，`FF` 为全体；`10` 的实际计算遵循游戏及引擎，界面不预估角色的运行时距离。未知或补丁编码从同一控件的“自定义编号…”编辑。选择一个预设只写当前字段，保留其他效果、未知位、指针和未解释字节，并复用原有撤销历史。固定来源见[道具类型、等级与射程](../sources.md#道具类型等级与射程)。

## 道具效果

道具 `+30:u8` 为使用效果字段、`+31:u8` 为武器效果字段。`records.Format.ItemUseEffects`／`ItemWeaponEffects` 由各版本配置声明，`ItemChoices` 返回编号、名称和说明的独立副本。名称注册表只确认原版用途；使用效果字段可参与菜单显示与分类，实际目标选择和行为仍存在按道具 ID 的原生分派，不能将改一个编号描述为安装或替换使用程序。

| 字段／编号 | 原版语义及版本差异 |
| --- | --- |
| 使用效果 `01` | FE6 为封印之剑回复，FE7／FE8 为治疗杖；FE6 治疗杖是 `02` |
| 使用效果 `29` | FE6 为缇娜杖，FE7 为铁之守护用途，FE8 为法拉之力用途 |
| 使用效果 `2A–32` | 舞蹈戒指、成长物品及转职物品在 FE7／FE8 间有编号差异，分别声明 |
| 武器效果 `00–02` | 无附加效果、中毒、吸血 |
| 武器效果 `03` | FE6 Eclipse 使用目标当前生命减 1 的特殊伤害；FE7／FE8 使用半血特殊伤害 |
| 武器效果 `04` | 原生恶魔反噬，概率和其他条件遵循游戏版本 |
| 武器效果 `05` | FE8 石化；FE6／FE7 不注册该原生选项 |

重名使用效果保留独立编号，例如 FE7／FE8 的两条宝箱钥匙用途。旧版标成问号的 FE7 `33–35`、FE8 `2F`／`33–35`，以及 IER 扩展的 `37`／`38` 不注册为已确认原生选项；当前值仍可读取和通过“自定义编号…”编辑。FE6 Watch 作为已命名的原版预留用途列出，并说明未确认可用处理。选择或编辑仅修改当前效果字节，不自动修改道具 ID、特性、能力加成指针、另一效果字段或处理代码。失败、历史与保存继续复用记录字段写入。固定依据见[道具效果](../sources.md#道具效果)。

## 道具特性

道具的 `+8:u32` 标志通过独立的 `records.Format.ItemTraits` 建模，`RecordTraits(Items)` 提供位号、已确认状态、语义分组、名称与说明。FE6 确认低 15 位，FE7／FE8 确认低 22 位；其余位不因某份 ROM 中为零而获得可写语义。版本与[固定来源](../sources.md#道具特性)一同约束解释。

| 道具位 | FE6 | FE7 | FE8 |
| --- | --- | --- | --- |
| 10 | 龙族武器锁 | 龙族武器锁 | 魔物武器锁 |
| 11 | 罗伊武器锁 | 武器锁 1 | 武器锁 1 |
| 13 | 塞菲尔武器锁 | Prf 显示 | Prf 显示 |
| 15 | 未解释 | 必杀无效 | 必杀无效 |
| 16 | 未解释 | 需要解封 | 需要解封 |
| 17 | 未解释 | 无视防御 | 无视防御 |
| 18／19 | 未解释 | 艾利乌德／海克托尔锁 | 艾瑞珂／伊弗列姆锁 |
| 20／21 | 未解释 | 琳／阿托斯锁 | 原生武器锁 6／7，常规道具未使用 |

`SetRecordTrait(Items, ...)` 复用字段写入与原子历史，只修改指定已确认位。武器、魔法与杖分类保持独立；设置 Prf 显示不会自动清零熟练度，设置武器锁不会修改人物或职业标志，设置解封位不会写入运行时解封记录。未知位的设置／清除请求被拒绝；勾选其他特性保留未知位、未解释字节及独立引用。主表单以语义复选框替代整段 flags 输入，已设置的未知部分只读呈现。

## 空间分配与表搬迁

依据 `InputFormRef.WriteBinaryData`／`MoveBinaryData`、`MoveToFreeSapceForm` 和各版表初始化规则。搬迁入口见[使用指南](../user-guide.md)；自动搬迁要求已有表的范围和引用可确定。

| 行为／状态入口                                                                                          | 版本／依据                         | 行为与限制                                                                                  |
| ------------------------------------------------------------------------------------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------- |
| [末尾分配、对齐与容量](../coverage.md#storage-append)                                                   | 五版；最大 32 MiB                  | 4 字节对齐，新字节填 FF；不根据零或 FF 自动复用空间                                         |
| [有来源的可用区间](../coverage.md#storage-free-ranges)                                                  | 显式声明及边界检查                 | 检查已知表、源区、引用和其他保护区冲突                                                      |
| [更新已确认引用](../coverage.md#storage-references)                                                     | 游戏规则或显式引用                 | 核对当前指针值；外部、内部及资源内偏移引用分别解释，未选定共享引用和源数据保留              |
| [已有表搬迁](../coverage.md#storage-table-move)                                                         | 五版人物／职业／道具／章节表       | 包含 FE6 隐藏人物 ID 0 和职业／道具／章节结束记录；记录数不变；手动解析布局暂不提供自动搬迁 |
| [扩容与历史](../coverage.md#storage-expansion-history)                                                  | ROM 文档                           | 先验证再提交，一次撤销恢复原长度，重做恢复扩容；过期或其他文档的预览被拒绝                  |
| [表记录与容量规则](../coverage.md#storage-table-grow)、[旧区与共享引用](../coverage.md#storage-reclaim) | 表布局、游戏寻址规则和已确认使用方 | 保留旧区，不自动清空或回收；仅凭字节为空不能证明容量或引用规则                              |

资源写入由 `romwrite/plan_builder.go` 的 `Builder` 组合为一个 `WritePlan`；接口契约和调用示例见 `romwrite/doc.go`：

| 操作                              | 语义与边界                                                                                                           |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `Append`／`Replace`               | 对齐追加已编码载荷；Replace 同时更新显式选定的指针，核对预期原始字与写入归属，保留旧载荷。                           |
| `AppendEncoded`／`ReplaceEncoded` | 将目标文件偏移传给领域编码器，在同一操作中完成编码与加入计划；编码失败不占用空间，回调不得修改同一构建器。           |
| `Relocate`                        | 复制已声明的源区并修正选定外部／内部引用；与其他操作共享分配和冲突检查，外部引用与复用区间执行保护，源区保持不可写。 |
| `Repoint`／`ClearPointer`         | Repoint 的目标是文件偏移，0 指向 ROM 起点；ClearPointer 写入空指针，领域含义由调用方确认。                           |
| `Patch`                           | 覆盖原文件中的定长区间，执行区间保护，不平移后续字节；未知位在领域草稿编码时保留。                                   |
| `Plan`                            | 返回 `romwrite.WritePlan` 独立副本；Destination 是所有分配的外包区间，不赋予中间空隙的写入权限。                     |

`edit.Context.Capture()` 将快照字节与 `Stamp` 一起返回为 `edit.Input`；`CaptureBytes()` 只用于不依赖解析设置的操作。`edit.NewCommit` 将写入和原始 stamp 冻结为 `edit.Commit`，不重新执行资源归属检查。旧草稿不能通过重新捕获输入绕过过期判断。

同一构建器中的操作共享分配位置；重复或交叠写入会在规划时失败，不以调用顺序覆盖。任一操作失败不会留下部分写入或消耗分配空间；已有成功操作仍可保留并继续规划。原始快照在构建期间保持只读，预览及提交仍需使用同一文档、修订和适用解析设置。多字段修改应先在领域草稿中合成为最终字节，再交给构建器。

未知补丁新增的引用可能不在当前规则中。源数据保留，因此旧引用仍有效，但这些使用处可能读不到搬迁后的修改。

## 改版识别与写入判定

固定旧版基线的行为依据：

- `ROM.LoadLow` 按 ROM 标头和最小长度选择游戏实现，另有 `LoadForceVersion`；这不是对整个改版布局的认证。
- `PatchUtil.SearchSkillSystemLow` 和 `MagicSplitUtil.SearchMagicSplitLow` 通过已知字节特征识别补丁。没有匹配时返回 `NO`，未单独返回“未知补丁”状态。
- `UnitForm_Load` 根据识别结果显示技能入口和魔力拆分字段，属于局部能力适配。
- `U.FindROMPointer` 在候选指针中查找，有的重载额外检查结构；检查失败会逐级回退，最终可能返回第一个候选。
- `InputFormRef.WriteHandler` 检查受保护地址、表范围、ID 0 和对齐。部分检查支持配置成直接允许、询问或拒绝；其范围检查在原始边界不明时也存在放行路径。这些检查不等于对结构化布局正确性的保证。

上述读取和写入路径没有统一按已识别改版或未知改版划分编辑权限。现有检测也无法保证发现所有未知改动。

新版按游戏版本、已知补丁和通用表规则提供编辑。未匹配补丁名单不会单独触发只读。

发现非法地址、无效长度、布局冲突或无法确定写入位置时，停止本次自动结构化写入并说明原因。用户可指定布局或地址后重新检查，也可编辑原始字节。原始修改仍检查边界，并使用统一撤销历史。

保留未知字节不等于能安全搬迁它们；引用不明确时，不自动移动未知结构。未知自定义布局可能超出自动识别范围。

# 战斗与死亡对话

这些全局表与章节普通对话条件分开。旧版入口为 `EventBattleTalkForm`、`EventBattleTalkFE7Form`、`EventBattleTalkFE6Form` 以及三个 `EventHaiku*Form`；原生代码、版本字节及固定提交见[核对来源](../sources.md#战斗与死亡对话)。功能状态见[覆盖矩阵](../coverage.md#战斗与死亡对话)，操作见[使用指南](../user-guide.md#战斗与死亡对话)。

## 记录布局

所有整数均为 little-endian，下面偏移为十六进制，宽度以位计。表中未列出的字节原样保留；新增记录的未解释字节为零，复制记录保留完整原字节。

| 版本与表                      | 步长 | 角色与条件                                | 文本、脚本及标志                                          |
| ----------------------------- | ---- | ----------------------------------------- | --------------------------------------------------------- |
| FE6 指定双方                  | 12   | A `+0:u8`、B `+1:u8`、章节 `+2:u8`        | 文本 `+4:u32`、标志 `+8:u32`                              |
| FE6 通用／三角攻击            | 16   | 角色 `+0:u8`、章节 `+1:u8`                | 文本 `+4:u32`、标志 `+8:u32`；最后四字节不解释            |
| FE6 死亡                      | 16   | 角色 `+0:u8`、章节 `+1:u8`                | 死亡文本 `+4:u32`、标志 `+8:u32`、终章文本 `+C:u32`       |
| FE7J/U 指定双方               | 16   | A `+0:u8`、B `+1:u8`、章节 `+2:u8`        | 文本 `+4:u32`、脚本 `+8:u32`、标志 `+C:u32`               |
| FE7J/U 通用／三角攻击         | 12   | 角色 `+0:u8`、章节 `+1:u8`                | 文本 `+4:u32`、标志 `+8:u32`                              |

| FE7J/U 琳篇／其他篇章死亡脚本 | 12   | 角色 `+0:u8`、章节 `+1:u8`                | 脚本 `+4:u32`、标志 `+8:u32`                              |
| FE8J/U 战斗                   | 16   | A `+0:u16`、B `+2:u16`、章节 `+4:u16`     | 标志 `+6:u16`、文本 `+8:u16`、脚本 `+C:u32`；`+A…+B` 保留 |

FE6／FE7 的双方表以 **B 的字节为零**结束，其他表以角色字节为零结束；FE8 两表以首个半字 `FFFF` 结束。读取和追加均要求完整终止记录，重定位时保留该记录的其余字节。FE8 的全零记录不是终止符；不采用旧版连续空白启发式。每张表最多读取 2048 条正文记录，超过上限或缺少原生终止符时报告无效表。

新角色值限制在原生 8 位 ID 范围内，字段本身仍按上述宽度存储。若既有 FE8 角色字超过 `FF`，人物选择器和领域字段修改均停止覆盖该字，其他字段仍可编辑。旧版 `DeathQuoteAddKillerID` 扩展会使用死亡记录的 `+1` 字节；当前不会自动把它解释成击杀者，也不会用普通人物选择覆盖它。其他补丁专用条件通过原始字节处理。

## 匹配及执行

同一张表保留原生匹配顺序；搜索不会改变顺序，移动记录会改变优先级。

- **FE6**：先检查双方表，人物顺序可交换；再依次检查攻击方、反击方的通用表，最后检查攻击方的三角攻击表。章节 `2D` 通配，已设置的标志会跳过该记录。死亡表的 `+C` 由终章流程读取，不是死亡播放时的第二段文本。罗伊死亡的原生特殊处理独立于表中的普通标志。
- **FE7J/U**：双方表同样双向匹配，章节通配分别为 `45`／`43`。双方查找先命中记录，再检查其标志；已置位时不会继续找后续双方记录或通用表。其他战斗表依次按两个角色、三角攻击回退。`gPlayStatus` 的 `+14` 位 `80` 会跳过双方表。死亡检查先查普通表，再查对应篇章脚本表；实际显示先查篇章脚本表，再回退到普通表，不能将两类表合并排序。篇章脚本表的 `65` 标志还参与游戏结束音乐与状态处理。
- **FE8J/U**：按表序检查章节和标志。双方都非零时双向匹配；仅 A 非零时匹配攻击方，仅 B 非零时匹配反击方；两者都为零时跳过。章节 `FF` 通配，战斗表的 `FE` 在章节相等或三角攻击时通过。死亡路线 `FF` 通配，`00`／`01`／`02` 对应共同／艾瑞珂／艾弗拉姆路线；死亡表按路线、章节、未置位标志和角色查找。非零文本优先于脚本；两者皆零的死亡记录仍通过 `SetPidDefeatedFlag` 设置标志。

FE8 的遭遇战和行动类型仍会限制战斗对话；死亡角色、章节保护角色、遭遇战及 `65` 标志共同影响 `SetPidDefeatedFlag`。编辑完成标志不等于修改所有游戏结束规则，也不会自动调整章节胜败脚本。FE6／FE7 某些战斗分支直接使用文本或脚本，填写引用时应为该分支提供实际内容。

`game/quote` 持有表格式、记录原字节和绑定文档／修订／布局的草稿。计划冻结完整新表、终止记录、已知原生入口和文件长度，统一追加并提交一次历史。即使仅修改一个字段也采用这一流程，不回收旧表。共享旧地址的其他独立表保留其入口及旧数据；预览单列这些共享处。若同一原生表的已知消费者已分离，报告 `game.quote_reference_conflict`，不按指针相似性合并。

正文、完整终止记录和原生入口参与跨资源写入保护。已声明脚本的首四字节仅作为最小读取范围保护，不代表已确认完整脚本长度或可回收空间。新选文本须能读取；新选脚本须为 ROM 中四字节对齐且至少可读四字节的地址，零表示无引用。不变的既有字段和未知字节按原样保留。失败、超容量、跨文档或过期操作不写入部分数据。

此页编辑脚本引用，并可跳转到脚本原始字节；不会把这些全局调用入口擅自归到某一章，也不据此赋予地图或部署编辑上下文。文本使用处索引包含这些表及 FE6 终章台词，可以返回所属记录。自定义代码持有的额外表引用、补丁专用布局、完整全局脚本图和独立对话脚本的结构编辑不由这些原生入口证明。

# 支援关系、对话与属性加成

旧版入口为 `SupportUnitForm`／`SupportUnitFE6Form`、三版 `SupportTalk*Form` 及 `SupportAttributeForm`。版本与原生消费者依据见[核对来源](../sources.md#支援关系与对话)，功能状态见[覆盖矩阵](../coverage.md#原生支援)，操作见[使用指南](../user-guide.md#支援)。

## 人物关系

按当前人物表的每条记录 `+2C` 指针读取关系，包括手动布局；零指针与损坏指针分开处理。不会从旧版全局支援起点向后扫描空白猜测记录数，也不要求各人物的关系数据连续。

| 版本           | 保留长度 | 对象 ID   | 初始值    | 每次增长值 | 有效人数       |
| -------------- | -------- | --------- | --------- | ---------- | -------------- |
| FE6            | 32 字节  | `+00…+09` | `+0A…+13` | `+14…+1D`  | `+1E`，最多 10 |
| FE7J/U、FE8J/U | 24 字节  | `+00…+06` | `+07…+0D` | `+0E…+14`  | `+15`，最多 7  |

字段均为无符号字节。有效人数决定游戏读取的前缀，未使用槽位及末尾字节按原样保留。新增在有效前缀末端写一个槽位并增加人数；删除移动后续有效槽位，清零原最后一个有效槽位并减少人数，其他未使用槽位保留。新建对象须为当前人物表中的非零原生 ID，不能指向自身或与其他有效槽位重复。人数超出原生容量、指针无效或读取越界时停止结构化编辑。

空指针可通过添加对象初始化独立记录。删除所有对象保留人数为零的有效记录，不回收旧区。每次修改均追加完整保留长度，仅更新选定人物指针；其他人物即使原先共享相同数据，也继续使用原副本。

“同步已有反向关系的数值”默认关闭。启用后，对新增或数值发生变化的对象查找其有效前缀内的反向关系，只同步初始值和增长值；双方修改组成同一个计划。不存在反向关系时在预览中列出，不替另一方新增、删除或重排关系；损坏记录或重复反向匹配停止本次计划。未改变的关系不会触发同步，也不修改存档中已有的支援进度。

支援属性加成表是独立数据，由[属性加成面板](#属性加成)编辑；关系操作不改变该表或人物属性字段。

## 原生对话

整数按 little-endian 存储。关系和对话独立：调整人物关系不隐式创建、删除或修改对话配对。

| 版本   | 步长 | 人物双方             | C／B／A 文本      | 原生结束条件    |
| ------ | ---- | -------------------- | ----------------- | --------------- |
| FE6    | 16   | `+00:u8`、`+01:u8`   | `+04/+08/+0C:u32` | 首字节为零      |
| FE7J/U | 20   | `+00:u8`、`+01:u8`   | `+04/+08/+0C:u32` | 首字节为零      |
| FE8J/U | 16   | `+00:u16`、`+02:u16` | `+04/+06/+08:u16` | 首半字为 `FFFF` |

匹配允许双方交换，首个匹配项生效。读取要求完整终止记录，最多 2048 条；FE6／FE7 不沿用旧版“两字节同时为零”的终止启发式。重复配对保持顺序并分别显示。新选文本 ID 为 0…65535，非零须能从当前主文本表读取；未改动的既有宽字段值保持原样。

本流程只编辑现有对话的文本 ID，保留双方、记录顺序、音乐字段、未解释字节及完整终止记录。FE7 的 `+10` 音乐字和 FE8 `+0C` 的音乐位段继续保留。回想及存档逻辑依赖表序，因此没有将增删排序作为普通文本替换的一部分。文本页面的使用处包含这些现有记录，可定位到独立支援对话面板的对应条目。

下表均为保存指针的 ROM 偏移；解析使用当前目标，不绑定原版表地址。

| 版本 | 已确认消费者                                                                    |
| ---- | ------------------------------------------------------------------------------- |
| FE6  | `6AFE0`                                                                         |
| FE7U | `78A94`、`78B04`、`78B64`、`9B164`、`9B18C`、`9EC2C`、`9ECF4`、`9EE00`、`9EE70` |
| FE7J | `79264`、`792D4`、`79334`、`9BB38`、`9BB60`、`9F668`、`9F730`、`9F83C`、`9F8AC` |
| FE8U | `84784`、`847FC`                                                                |
| FE8J | `86A50`、`86AC8`                                                                |

对话修改追加完整表并一起更新这些消费者，包括战场播放、回想及存档统计所需入口。已知消费者分离时报告 `game.support_reference_conflict`，对话写入停止，独立人物关系仍可编辑。形似指针的其他字节不参与更新，自定义调用未完整索引。

## 属性加成

五版都使用 8 字节记录：`+00` 为属性 ID，`+01…+06` 依次为攻击、防御、命中、回避、必杀和必杀回避，`+07` 保留。六项值均为无符号字节，编辑范围为 0–255。原生消费者逐条比较属性 ID，首个匹配项生效；ID 为零时结束。读取要求完整的 8 字节结束记录，最多 256 条非结束记录，实际目标须为有界、四字节对齐的 ROM 地址。零指针、越界、未结束或超限表停止自动编辑。

| 版本 | 原生查找器的表指针位置 |
| ---- | ---------------------- |
| FE6  | `22DBC`                |
| FE7U | `26998`                |
| FE7J | `26E24`                |
| FE8U | `28534`                |
| FE8J | `284C8`                |

按当前指针读取，允许已搬迁的表、额外属性 ID 和重复 ID。只修改现有记录的六项加成，保留 ID、表序、每条尾字节及完整结束记录，不增删或重排。名称采用原生属性标签，额外 ID 以编号显示；不据此认证改版引擎的计算方式。

原生引擎将双方各自属性的六项值乘以对应支援等级，以无符号字节累加所有适用支援，再将各项总值除以 2。大数值可能先按 256 回绕，不能把单个字段直接视作最终战斗增益。人物关系、支援等级、距离和可用状态影响实际生效；本编辑器不模拟战斗，也不修改存档中的等级。

`game/support/bonuses.go` 的 `BonusDraft` 保存全表草稿，`BonusPlan` 冻结变化及使用处。预览列出改变的值、该记录是否为首个匹配项，以及当前人物布局中具有相同属性的已确认人物；后续重复项不列生效人物。人物表读取失败会报告使用处不完整，不阻止独立加成表编辑。人物关系和对话数据损坏同样不影响有效加成表。

应用追加完整表，只更新上述选定原生消费者，旧表和其他独立引用保持原样。表、指针与文件长度组成一次提交；指针位置和已读出的表范围加入会话资源声明。未知的自定义消费者不会被扫描或自动更新。文档、修订及手动布局变化使旧草稿和计划失效，交叉占用或超过 32 MiB 时拒绝写入。

## 提交与保护

`game/support` 持有原生格式、关系草稿和对话草稿；`game/support_sources.go` 从记录编辑器提供当前人物入口及资源保护。预览绑定文档、修订和有效布局，冻结全部字节、指针及文件长度变化。人物面板将本人物关系与选中的反向同步组成一次历史操作；独立对话面板使用 `TalkDraft`／`PlanTalks`，无需读取有效关系记录即可规划现有对话修改。两个面板不混合各自的待应用内容，均复用不可变写入计划。更换文档、修改布局、产生新修订、资源交叉占用、无效文本或超过 32 MiB 都不会留下部分写入。

人物“支援”标签按人物保留关系草稿；独立对话面板保留全表的文本修改，以原生记录编号保存输入和筛选后的选择。关系行可按双方筛选对话，对话可返回双方人物标签或进入正文。非法输入阻止当前面板预览；布局变化及其他面板提交后，修改过或不完整的旧输入保留到明确放弃，不能把旧预览套到新修订。打开文本编辑正文也会产生新修订，可以先应用支援引用，再编辑正文。

五版合成流程检查原生字节、共享独立引用、双方同步、空入口初始化、终止记录、加成表首项匹配与额外 ID、冲突及失败原子性；动态 ROM 文件流程检查当前输入可编辑关系、对话和加成表的历史、保存与重开。这些证据不代表游戏内增长、支援触发或存档兼容已经执行验证。

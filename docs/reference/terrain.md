# 职业移动消耗与地形加成

本页说明原生职业表的移动消耗、回避、防御和魔防数据。功能状态见[覆盖矩阵](../coverage.md#职业移动与地形)，操作入口见[使用指南](../user-guide.md#职业移动与地形)。

## 布局与数值

入口取自当前职业记录，包括用户选择的手动布局。下表偏移为职业记录内的十六进制偏移，内容是 GBA ROM 指针。载荷按地形 ID 连续排列，无结束记录、无压缩；每项为一个有符号字节。

| 版本                   | 每列项数    | 普通消耗 | 雨天消耗 | 雪天消耗 | 回避 | 防御 | 魔防 |
| ---------------------- | ----------- | -------- | -------- | -------- | ---- | ---- | ---- |
| FE6                    | 51（00–32） | +34      | 无       | 无       | +38  | +3C  | +40  |
| FE7J／FE7U／FE8J／FE8U | 65（00–40） | +38      | +3C      | +40      | +44  | +48  | +4C  |

数值范围为 −128…127；`FF` 显示为 −1，是原生移动表常用的不可通行值。零及其他负数按原字节保留，不自动转换为 −1。消费者对非正消耗的检查及特殊移动规则各不相同，修改数值不构成对实际寻路效果的模拟。

地形名称使用原生 ID 的界面译名；未知 ID 仍可按编号编辑，不从名称推断规则，也不解码改版的地形名称表。弩车移动、地形回复、图块到地形的映射和自定义引擎规则分别有其他数据来源。

空指针、非 ROM 指针、长度不足和不完整职业记录按列报告。无效列不参与编辑，其余已确认的列仍可读取和修改。

## 计划与共享引用

草稿绑定文档、修订和当前记录布局。预览逐列列出改动值，以及仍读取原载荷的已知职业／天气入口；完整或局部重叠的载荷都纳入说明，未索引的自定义消费者不视为已确认。

每个改动列复制完整原生长度到 ROM 末尾，并只更新当前职业的相应指针。共用载荷的不同列即使同时修改，也分别分配，允许保存不同值。未修改值、原载荷、未知尾部、其他职业及天气入口保留；不回收原区，不扫描形似指针的字节来推断使用方。

全部新增载荷、指针和文件长度作为一次历史操作提交及撤销，最大文件长度为 32 MiB。指针字段与其他记录、资源入口或载荷重叠时停止自动写入；过期、跨文档和容量不足的操作不留下部分修改。无改动草稿不生成计划。

## 界面

职业详情的“移动与地形”标签按地形行、数值列排列，可用名称或十六进制 ID 筛选；窄窗口只横向滚动表格。输入停留在草稿，预览后再应用。空列和损坏列显示原因，原始数据模式提供地址及有效表的字节入口。

切换职业或暂时隐藏页面保留输入；文档／布局变化后，改过或尚未完成的输入保留并显示过期提示，需丢弃后重读。未改动的旧草稿自动刷新。搜索和数值输入使用文本撤销；应用后的修改进入统一 ROM 历史。

## 来源与验证

旧版来源为固定子模块的 `ClassForm.cs`、`ClassFE6Form.cs`、`MoveCostForm.cs`、`MoveCostFE6Form.cs` 及五版 `ROMFE*`。原生职业结构、地形编号和实际移动消费者的固定提交入口见[核对来源](../sources.md#职业移动与地形)。日版布局另与固定旧版日版定义及动态发现的 ROM 文件流程对照，不以美版源码证明全部日版或改版执行行为。

`internal/testutil/terrain.go` 独立编排五版字节。`game/terrain/workflow_test.go` 检查有符号值、独立与部分重叠引用、天气及加成共用、未知尾部、冻结计划、手动布局、过期冲突、容量、原子历史及保存重开。`tests/integration/terrain_test.go` 按当前文件的可用列选择入口，验证追加、未选中字节保留、历史及保存重开。文件流程和临时 UI 复核不替代游戏内寻路或战斗验证。

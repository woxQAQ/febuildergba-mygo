## 地图布局

地图布局写入依据旧版基线的 `MapEditorForm.WriteMapData`：宽、高各一字节，逐格 16 位小端图块值，整体 LZ77 压缩，再更新地图 PLIST 项。`MapPointerForm.GetBasePointer` 及五版 `ROMFE*` 定义各资源类型的实时列表入口，用于区分共用列表、拆分列表和跨资源类型的入口冲突。

布局与地形另外核对 FE8 同一固定提交的 [src/bmmap.c](https://github.com/FireEmblemUniverse/fireemblem8u/blob/04d1edb163d14bd10777a065697e1a9f17be65f2/src/bmmap.c)：`UnpackChapterMap` 读取宽高，`InitBaseTilesBmMap` 逐行读取 16 位图块，`RefreshTerrainBmMap`／`GetTrueTerrainAt` 用图块值右移两位索引地形，`DisplayBmTile` 读取四个连续的 8×8 图块。五版入口与文件写入分别由独立合成样本及动态发现的真实 ROM 文件流程核对；文件流程不等于游戏内执行验证。

尺寸操作另参考旧版 `MapEditorForm` 的地图大小修改及 `MapChangeForm.N_Init` 的条目布局。地图变化的实际读取核对固定 FE6 提交的 [src/chapterinfo.c](https://github.com/StanHash/fe6/blob/f9ea5f67f3f1048ca9836d7350077231ba54b589/src/chapterinfo.c)、[src/trap.c](https://github.com/StanHash/fe6/blob/f9ea5f67f3f1048ca9836d7350077231ba54b589/src/trap.c)、[include/unknown_types.h](https://github.com/StanHash/fe6/blob/f9ea5f67f3f1048ca9836d7350077231ba54b589/include/unknown_types.h)，固定 FE7U 提交的 [asm/code.s](https://github.com/StanHash/fe7_us/blob/5c8b3c5e254e00f0f3458b9772c27e1a5a326e3b/asm/code.s) 中的 `GetChapterMapChanges`／`GetMapChangeIdAt`，以及固定 FE8 提交的 [src/chapterdata.c](https://github.com/FireEmblemUniverse/fireemblem8u/blob/04d1edb163d14bd10777a065697e1a9f17be65f2/src/chapterdata.c)、[src/bmtrick.c](https://github.com/FireEmblemUniverse/fireemblem8u/blob/04d1edb163d14bd10777a065697e1a9f17be65f2/src/bmtrick.c) 和实际消费的 [include/types.h](https://github.com/FireEmblemUniverse/fireemblem8u/blob/04d1edb163d14bd10777a065697e1a9f17be65f2/include/types.h)。原生按 PLIST 值是否为空判定有无变化表，条目 ID 为有符号字节，所有负值均终止；旧版仅检查 `FF`，FE8 的另一份 `MapChangeInfo` 声明也不足以代表消费函数的有符号语义。FE7J 与 FE8J 另以原版对应循环的 `ldrsb`／`bge` 核对，日美条件一致。

坐标影响复用下述部署、REDA、条件事件及脚本来源。锚点和奇数差额的分配是编辑器的明确操作契约；不据此自动改变原生事件坐标或推断运行时状态。

## 地图变化与事件引用

变化表与图块编辑依据旧版基线的 [MapChangeForm.cs](../FEBuilderGBA/FEBuilderGBA/MapChangeForm.cs) 及上述三套原生资源消费者。FE6 的 `GetMapChange`／`ApplyMapChange`、FE7 的对应汇编和 FE8 的 `GetMapChange`／`GetMapChangeIdAt`／`ApplyMapChangesById` 确认逐行 uint16 载荷、零格不替换、ID 首条匹配及坐标最后覆盖 ID 再查首项的顺序。

脚本编码和副作用核对固定 FE6 的 [src/event.c](https://github.com/StanHash/fe6/blob/f9ea5f67f3f1048ca9836d7350077231ba54b589/src/event.c) 中 `EvtCmd_MapChange`／`EvtCmd_MapChangePosition`，固定 FE7U 的 [src/event.c](https://github.com/StanHash/fe7_us/blob/5c8b3c5e254e00f0f3458b9772c27e1a5a326e3b/src/event.c) 中变化、立即、静默、水面阴影及刷新函数，以及固定 FE8 的 [src/eventscr.c](https://github.com/FireEmblemUniverse/fireemblem8u/blob/04d1edb163d14bd10777a065697e1a9f17be65f2/src/eventscr.c) 的 `Event27_MapChange` 和 [src/eventscr_utils.c](https://github.com/FireEmblemUniverse/fireemblem8u/blob/04d1edb163d14bd10777a065697e1a9f17be65f2/src/eventscr_utils.c) 的 `TriggerMapChanges`／`UntriggerMapChange`，以及 [src/bmtrick.c](https://github.com/FireEmblemUniverse/fireemblem8u/blob/04d1edb163d14bd10777a065697e1a9f17be65f2/src/bmtrick.c) 的 `RevertMapChange`。FE7 日美分发表分别核对 5D–62／5F–64 的编号与一字长度；FE6 的 ID／坐标指令均为两字，FE8 两版使用 27 的应用／恢复子码。

FE6／FE7 坐标未命中退回事件参数，FE8 则返回事件错误。FE7 高位控制前一 ID 的启用状态，静默模式另有不启用当前 ID 的分支；FE8 恢复整个矩形，并按 signed halfword 消费队列 ID。以上规则分别有独立五版字节样本与动态文件流程；实际游戏内执行仍未验证。

## 地点条件与执行

地点表入口、12 字节记录、对象分类及商店引用依据固定旧版 `EventCondForm.InitObject`、`SupportOtherSeries`、`MakeShopPointerListBox` 和 `ItemShopForm.Init`。原生语义使用上表同一固定提交：

- FE6：[src/eventinfo.c](https://github.com/StanHash/fe6/blob/f9ea5f67f3f1048ca9836d7350077231ba54b589/src/eventinfo.c) 的 `EvtListCmd_Tile`／`TileWithMapChange`／`ItemChest`／`Door`／`Shop` 与 `StartAvailableTileEvent`；[include/constants/iids.h](https://github.com/StanHash/fe6/blob/f9ea5f67f3f1048ca9836d7350077231ba54b589/include/constants/iids.h) 确认金币标记 `6F`。
- FE7U：[asm/code.s](https://github.com/StanHash/fe7_us/blob/5c8b3c5e254e00f0f3458b9772c27e1a5a326e3b/asm/code.s) 的 `func_080784C0`、`func_0807850C`、`func_08078520`、`func_0807856C`、`func_080785F4` 核对坐标、命令单字节和关联数据；`08078CD8…08078DF2` 的地点执行分支确认事件宝箱、门、访问、商店和金币标记 `76`。FE7J 的表入口、命令及记录结构另核对固定旧版日版配置。
- FE8：[src/eventinfo.c](https://github.com/FireEmblemUniverse/fireemblem8u/blob/04d1edb163d14bd10777a065697e1a9f17be65f2/src/eventinfo.c) 的 `EvCheck05_LOCA`／`06_VILL`／`07_CHES`／`08_DOOR`／`0A_SHOP` 和 `StartAvailableTileEvent` 确认半字命令、门的单字节命令、随机奖励表与自动地图变化；[include/constants/items.h](https://github.com/FireEmblemUniverse/fireemblem8u/blob/04d1edb163d14bd10777a065697e1a9f17be65f2/include/constants/items.h) 确认金币标记 `77`。FE8J 的入口和记录布局另查固定旧版日版配置。

金币数量以实际消费者为准：FE8 同一提交的 [src/eventscr.c](https://github.com/FireEmblemUniverse/fireemblem8u/blob/04d1edb163d14bd10777a065697e1a9f17be65f2/src/eventscr.c) 中 `EventScr_OpenChest` 在 255 处分流道具和金币，因此新金币至少为 256、新道具最多为 255；FE6 的 [src/event.c](https://github.com/StanHash/fe6/blob/f9ea5f67f3f1048ca9836d7350077231ba54b589/src/event.c) 中 `StartChestMoneyEvent`／`EventScr_MoneyChest` 和 FE7U 的 [asm/event.s](https://github.com/StanHash/fe7_us/blob/5c8b3c5e254e00f0f3458b9772c27e1a5a326e3b/asm/event.s) 中 `func_0800F044`／`func_0800F06C` 使用独立奖励脚本，不套用旧版界面统一的 256 提示。五版独立合成记录验证固定字节，动态 ROM 流程验证当前输入的条件修改和保存重开；这些检查不等于游戏内执行。

## 商店货物

旧版来源仍为子模块固定基线：`ItemShopForm.Init` 的双字节条目及低字节结束规则、`MakeShopListLow` 的章节／准备／世界地图入口、`B0_ValueChanged` 与 `PatchUtil.ItemUsingExtendsPatchLow` 的 IER 高字节解释。章节类型由 `EventCondForm.MakeShopPointerListBox` 和各版地点执行器交叉核对；原生容量与读取长度以实际游戏消费者为准：

- FE6，`StanHash/fe6@f9ea5f67f3f1048ca9836d7350077231ba54b589`：[asm/code.s](https://github.com/StanHash/fe6/blob/f9ea5f67f3f1048ca9836d7350077231ba54b589/asm/code.s) 的 `func_fe6_08095E10`／`30`／`50` 传入商店类型 0／1／2，`func_fe6_08095E90` 从下标 0 复制到 `0x14`，每项调用 [src/item.c](https://github.com/StanHash/fe6/blob/f9ea5f67f3f1048ca9836d7350077231ba54b589/src/item.c) 的 `CreateItem`。
- FE7U，`StanHash/fe7_us@5c8b3c5e254e00f0f3458b9772c27e1a5a326e3b`：[asm/code.s](https://github.com/StanHash/fe7_us/blob/5c8b3c5e254e00f0f3458b9772c27e1a5a326e3b/asm/code.s) 的 `func_080B03D4`／`03F4`／`0414` 和 `func_080B0454`，同样复制 21 个半字并调用 `CreateItem`；`func_080B0520` 扫描生成后的结束项。FE7J 对应原版循环以 `cmp #0x14`／`ble` 和双字节步进核对，与旧版日版地点类型定义组合使用。
- FE8，`FireEmblemUniverse/fireemblem8u@04d1edb163d14bd10777a065697e1a9f17be65f2`：[src/bmshop.c](https://github.com/FireEmblemUniverse/fireemblem8u/blob/04d1edb163d14bd10777a065697e1a9f17be65f2/src/bmshop.c) 的 `StartShopScreen`／`UpdateShopItemCounts`，以及 [include/bmshop.h](https://github.com/FireEmblemUniverse/fireemblem8u/blob/04d1edb163d14bd10777a065697e1a9f17be65f2/include/bmshop.h) 的 20 项货物与紧随半字；[src/bmitem.c](https://github.com/FireEmblemUniverse/fireemblem8u/blob/04d1edb163d14bd10777a065697e1a9f17be65f2/src/bmitem.c) 的 `MakeNewItem` 按道具定义重建耐久。FE8J 由旧版准备商店指针处调用追踪到同类加载器，确认从 `0x14` 递减至 0 的 21 次双字节复制。

因此新分配保留完整 42 字节读取范围，20 项之后必须有结束项；原货物高字节和结束项高字节保留，未知尾部留在原位置。日版原生字节核对和五版动态文件流程不替代游戏内购买验证。

默认货物从上述加载器的空指针分支定位；FE8 准备界面另查同一固定提交的 [src/prep_itemscreen.c](https://github.com/FireEmblemUniverse/fireemblem8u/blob/04d1edb163d14bd10777a065697e1a9f17be65f2/src/prep_itemscreen.c) 中 `StartPrepArmory`／`gPrepShopInventory`。以下值是保存指针的 ROM 偏移，内容按当前 ROM 读取：

| 版本 | 引擎默认货物指针 | 准备商店指针 | 世界地图节点表指针 |
| ---- | ---------------- | ------------ | ------------------ |
| FE6  | 0x95F10          | 无           | 无                 |
| FE7U | 0xB04D4          | 无           | 无                 |
| FE7J | 0xB12FC          | 无           | 无                 |
| FE8U | 0xB42B0          | 0x99E64      | 0xBE84             |
| FE8J | 0xB8E38          | 0x9C144      | 0xC8DC0            |

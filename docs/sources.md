## 地图布局

地图布局写入依据旧版基线的 `MapEditorForm.WriteMapData`：宽、高各一字节，逐格 16 位小端图块值，整体 LZ77 压缩，再更新地图 PLIST 项。`MapPointerForm.GetBasePointer` 及五版 `ROMFE*` 定义各资源类型的实时列表入口，用于区分共用列表、拆分列表和跨资源类型的入口冲突。

布局与地形另外核对 FE8 同一固定提交的 [src/bmmap.c](https://github.com/FireEmblemUniverse/fireemblem8u/blob/04d1edb163d14bd10777a065697e1a9f17be65f2/src/bmmap.c)：`UnpackChapterMap` 读取宽高，`InitBaseTilesBmMap` 逐行读取 16 位图块，`RefreshTerrainBmMap`／`GetTrueTerrainAt` 用图块值右移两位索引地形，`DisplayBmTile` 读取四个连续的 8×8 图块。五版入口与文件写入分别由独立合成样本及动态发现的真实 ROM 文件流程核对；文件流程不等于游戏内执行验证。

尺寸操作另参考旧版 `MapEditorForm` 的地图大小修改及 `MapChangeForm.N_Init` 的条目布局。地图变化的实际读取核对固定 FE6 提交的 [src/chapterinfo.c](https://github.com/StanHash/fe6/blob/f9ea5f67f3f1048ca9836d7350077231ba54b589/src/chapterinfo.c)、[src/trap.c](https://github.com/StanHash/fe6/blob/f9ea5f67f3f1048ca9836d7350077231ba54b589/src/trap.c)、[include/unknown_types.h](https://github.com/StanHash/fe6/blob/f9ea5f67f3f1048ca9836d7350077231ba54b589/include/unknown_types.h)，固定 FE7U 提交的 [asm/code.s](https://github.com/StanHash/fe7_us/blob/5c8b3c5e254e00f0f3458b9772c27e1a5a326e3b/asm/code.s) 中的 `GetChapterMapChanges`／`GetMapChangeIdAt`，以及固定 FE8 提交的 [src/chapterdata.c](https://github.com/FireEmblemUniverse/fireemblem8u/blob/04d1edb163d14bd10777a065697e1a9f17be65f2/src/chapterdata.c)、[src/bmtrick.c](https://github.com/FireEmblemUniverse/fireemblem8u/blob/04d1edb163d14bd10777a065697e1a9f17be65f2/src/bmtrick.c) 和实际消费的 [include/types.h](https://github.com/FireEmblemUniverse/fireemblem8u/blob/04d1edb163d14bd10777a065697e1a9f17be65f2/include/types.h)。原生按 PLIST 值是否为空判定有无变化表，条目 ID 为有符号字节，所有负值均终止；旧版仅检查 `FF`，FE8 的另一份 `MapChangeInfo` 声明也不足以代表消费函数的有符号语义。FE7J 与 FE8J 另以原版对应循环的 `ldrsb`／`bge` 核对，日美条件一致。

坐标影响复用下述部署、REDA、条件事件及脚本来源。锚点和奇数差额的分配是编辑器的明确操作契约；不据此自动改变原生事件坐标或推断运行时状态。

## 地图变化与事件引用

变化表与图块编辑依据旧版基线的 [MapChangeForm.cs](../FEBuilderGBA/FEBuilderGBA/MapChangeForm.cs) 及上述三套原生资源消费者。FE6 的 `GetMapChange`／`ApplyMapChange`、FE7 的对应汇编和 FE8 的 `GetMapChange`／`GetMapChangeIdAt`／`ApplyMapChangesById` 确认逐行 uint16 载荷、零格不替换、ID 首条匹配及坐标最后覆盖 ID 再查首项的顺序。

脚本编码和副作用核对固定 FE6 的 [src/event.c](https://github.com/StanHash/fe6/blob/f9ea5f67f3f1048ca9836d7350077231ba54b589/src/event.c) 中 `EvtCmd_MapChange`／`EvtCmd_MapChangePosition`，固定 FE7U 的 [src/event.c](https://github.com/StanHash/fe7_us/blob/5c8b3c5e254e00f0f3458b9772c27e1a5a326e3b/src/event.c) 中变化、立即、静默、水面阴影及刷新函数，以及固定 FE8 的 [src/eventscr.c](https://github.com/FireEmblemUniverse/fireemblem8u/blob/04d1edb163d14bd10777a065697e1a9f17be65f2/src/eventscr.c) 的 `Event27_MapChange` 和 [src/eventscr_utils.c](https://github.com/FireEmblemUniverse/fireemblem8u/blob/04d1edb163d14bd10777a065697e1a9f17be65f2/src/eventscr_utils.c) 的 `TriggerMapChanges`／`UntriggerMapChange`，以及 [src/bmtrick.c](https://github.com/FireEmblemUniverse/fireemblem8u/blob/04d1edb163d14bd10777a065697e1a9f17be65f2/src/bmtrick.c) 的 `RevertMapChange`。FE7 日美分发表分别核对 5D–62／5F–64 的编号与一字长度；FE6 的 ID／坐标指令均为两字，FE8 两版使用 27 的应用／恢复子码。

FE6／FE7 坐标未命中退回事件参数，FE8 则返回事件错误。FE7 高位控制前一 ID 的启用状态，静默模式另有不启用当前 ID 的分支；FE8 恢复整个矩形，并按 signed halfword 消费队列 ID。以上规则分别有独立五版字节样本与动态文件流程；实际游戏内执行仍未验证。

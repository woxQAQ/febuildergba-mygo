# 架构与代码导航

本文的模块与操作章节描述当前实现；[约束](#约束)是实现必须遵守的设计规则，不能随实现偏差改写；[未决问题](#未决问题)记录尚未选定的设计及决策触发条件。产品范围与逐项状态分别见[重建计划](rebuild-plan.md)和[覆盖矩阵](coverage.md)，开发执行约束见 [AGENTS](../AGENTS.md)。

`Session.Records`、`Session.Texts` 等字段直接提供所属包的编辑器；章节协调器与会话引用的是同一组地图、事件和部署编辑器。

记录的字段、布局、搬迁及人物／职业规则共享同一编辑模型，位于 `records` 包内；独立资源由各自领域包承接。[元数据设计](metadata-design.md)的接入触发条件见 [AGENTS](../AGENTS.md#开始修改)。

包名表达稳定职责：`edit` 管理提交有效性，`internal/editor` 管理窗口编辑状态；`portrait`、`itemicon` 管理原生资源，`graphics` 管理共享 PNG 流程。

图中展示主要依赖。`main.go` 只负责启动。下列直接导入约束由 `.golangci.yml` 的 `depguard` 随 `just lint`／`just check` 自动检查，包含子包和测试文件：

- `game`、`rom`、`space`、`gba`、`fault` 不导入 MyGo 或界面层。
- `game` 的领域子包不导入 `game/version`；版本身份由组合根选择。
- `app` 只经 `pages` 根包组合界面，不导入组件或页面子包。
- 组件不反向导入页面或 app，页面不导入 app；文本、头像、脚本、商店、支援、斗技场、战斗／死亡对话及世界地图页面不直接导入记录页。
- `locales` 不导入领域包；错误到文案的映射由组件承接。
- `internal/applog` 只依赖标准库与 `fault`；`game`、`rom`、`space`、`gba`、`fault`、`internal/input`、`internal/locales` 不导入它。
- `internal/input` 不导入 MyGo；该包独立承载纯数值和地址解析。

### 人工审查的设计约束

以下规则不由 depguard 证明，代码审查需结合实际调用和领域工作流验证：

- **版本事实**：生产配置中的绝对 ROM 地址（指针位置、hook、指令位置、恢复地址、补丁特征位置）只放在 `game/feXX.go`。领域包以命名值定义结构差异，例如 `support.FE7Layout()`、`chapter.FE6Layout()`、`records.FE7ClassFields()`；不以布尔值或版本 ID 选择版本，也不自行推导版本地址。页面通过领域 Format 的能力字段读取规则，如 `quote` 的 `BattleConditions`／`SilentDeath`。depguard 只覆盖上节的 `game/version` 导入限制，不检查地址或布局的放置。既有字面量例外见[未决问题](#未决问题)。
- **资源声明**：`space.Claim` 表示带所有者（Owner）的字节区间，Host 表示容纳指针站点的宿主记录。指针写入与声明重叠时，只允许写入者自己的站点声明或其宿主记录，由 `space.CheckWrite` 执行；原地载荷写入由 `space.CheckRangeWrite` 检查整段区间，只允许自己的声明及自己容纳的指针站点，其余均冲突。各领域声明自己的已确认资源，会话汇总；新增领域提供 Claims 来源，不给其他领域增加成对排除分支。实现审查检查来源是否齐全，领域流程检查冲突和失败原子性；已有声明不等于完整的全 ROM 引用证明。
- **包与资源边界**：子包不访问父包私有成员，父包不为子包逐项转发 API。原生编辑器接收所属格式、编辑上下文及具体资源输入，不接收整个 `*game.Session`。拆包依据是独立领域含义，不是文件数量。
- **状态与事务**：线程、异步结果、不可变计划及原子提交遵循 [AGENTS 的实现边界](../AGENTS.md#实现边界)；验证范围见 [AGENTS 的命令与验证](../AGENTS.md#命令与验证)。导入检查不能证明这些行为。

## 领域协作

世界地图场景的头像操作数通过 `event.Source.Portraits` 使用当前头像编辑器验证，`chapter.Config` 转交组合根的实例；页面消费同一资源的预览与名称，缓存绑定文档、修订和布局，不解释原始指令位。

`event` 解释指令并输出类型化的地图操作数、可确认坐标和不确定性；`chapter` 再查找地图资源、关联共享章节并汇总影响。`maps` 不读取事件解释器的私有指令行，`deployment` 不反向扫描事件图。地点条件通过 `Condition.OperandKind` 区分脚本、直接奖励、商店和随机奖励等目标；`event` 只把确认的脚本引用加入脚本图，`chapter` 消费地点坐标生成地图尺寸影响。资源所有者提供已确认区域和引用，当前操作负责组合保护范围；这些事实不代表完整的全 ROM 引用证明。

## 文档与编辑操作

每个窗口拥有独立的 `rom.Document` 和 `game.Session`。`rom` 保存字节、修订、撤销历史与保存点；领域编辑器各自保存解析结果和缓存。手动表定位由 `records` 管理，并向共享的 `edit.Context` 发布解析设置；它不改写 ROM 指针，也不增加 ROM 修订。

`edit.Context.Capture()` 返回 `edit.Input`，将只读快照字节与同次捕获的 `edit.Stamp` 放在一起；草稿只保留原始 stamp，不能重新捕获来延长旧草稿的有效期。stamp 绑定文档身份、修订和适用解析设置；设置恢复为相同内容时，解释身份也相同。`CaptureBytes()` 用于不依赖解析设置的操作，仍检查文档与字节修订；解释表、图像、部署、事件或地图的操作还必须检查布局。记录编辑器只有在新布局校验成功后才发布设置并重新捕获输入。

普通字段的有效数值直接进入文档；文本、批量、素材、地图、部署和事件保留草稿及不可变计划。包边界不决定事务边界：例如条件事件创建增援时，事件编码与部署编码分别由所属包完成，条件、脚本、单位载荷、指针及文件长度仍组成一个计划，通过一次 `rom.Document.ApplyEdit` 提交和撤销。章节商店同样由条件草稿持有独立的 `shop.Draft`，组合货物载荷和完整地点表，只更新选定地点引用；货物包不读取章节或持有窗口状态。独立商店使用 `shop.EntryDraft`／`shop.EntryPlan` 绑定所选入口、载荷和文件长度；`game/shop_sources.go` 按版本组合章节、默认、准备和节点引用，并保护其他已确认资源。`worldmap` 编辑已有原生节点字段；其 `Draft`／`Plan` 与商店货物独立，原地写入前检查整条节点的会话资源声明。`Format.Claims` 拥有节点及其商店指针宿主关系，会话仅汇总。`game/worldmap_sources.go` 提供当前章节／文本引用校验和资源保护，地名进入文本共享使用处。节点和路线表不自动搬迁。`RouteDraft`／`RoutePlan` 维护一条路线的端点、移动控制点及 `RoadDraft` 道路布局：端点原地修改，变化的轨迹和道路由同一追加计划分配并只更新所选指针，清空轨迹写零指针，空道路写有效结束流。`roads.go` 持有格子的显式写入状态、绘制笔画历史和稀疏编码。整条路线与会话声明检查交叠；原载荷、独立引用和未知字节保留，全部写入共享一次历史。`scene.go` 组合日间／暗色底图和道路流，图形错误与端点编辑独立，结果按同一 stamp 缓存。`background.go` 持有底图的不可变资源副本、索引 PNG 编解码及替换计划；变化的像素／调色板／调色板地图独立追加，暗色导入只改变配色。`road_tileset.go` 解析共享道路图块与配色，索引 PNG 替换保持数量与编号；预览可组合当前道路布局草稿。两类素材通过会话保护已确认入口，保留其他引用与未知字节。后台只消费 `Background`／`RoadTileset` 副本，生成导入结果后通过窗口回传，由 UI 线程检查来源并规划／应用。失败、跨文档或过期操作不得留下部分修改。

`terrain` 按当前职业记录读取移动与加成列，`game/terrain_sources.go` 提供自动／手动布局与资源保护。每个改动列独立追加，仅更新所属指针；共用或部分重叠的原载荷保持不变。`pages/records` 的职业标签消费领域草稿和计划，数值输入不直接写入 ROM。格式见[地形参考](reference/terrain.md)。

`support` 按当前人物指针解释关系，`game/support_sources.go` 提供有效人物布局、文本校验及外部资源保护。人物关系与可选的已有反向数值同步在 `pages/records` 的人物标签编辑；`pages/supports` 独立浏览对话表，使用 `TalkDraft`／`PlanTalks`，无需人物关系可读。两类草稿各自预览、应用，并复用同一领域写入计划；对话消费者包含回想和存档统计入口，表序及未知字节保留。人物、对话与文本通过回调导航；人物页按人物保留关系输入，对话页按原生条目保留文本输入，非法及过期输入都需明确丢弃。全局属性加成由同包的 `BonusDraft`／`BonusPlan` 管理，`pages/supports` 在独立标签内编辑六列原生值；关系、对话和加成各有草稿。加成计划按当前人物布局列出首个匹配项的已知使用处；人物表不可读时报告不完整，有效全局表仍可独立操作。格式见[支援参考](reference/supports.md)。

`arena` 解释三组职业字节列表、固定武器缓冲区和 FE8 联机名单，`game/arena_sources.go` 从当前记录布局提供职业层级与引用 ID，并连接会话资源保护。基础武器和升级表共用草稿，其他组独立；已确认基础武器消费者必须一致并一起搬迁。`pages/arenas` 按组保留输入、选择与预览，通过组合回调跳转职业、道具、人物及字节页面。普通字段消费领域行和类型，不从显示名称推断规则。格式见[斗技场参考](reference/arena.md)。

`quote` 表示战斗与死亡台词领域。`game/quote/format.go` 声明表结构、终止规则及命名能力字段，`editor.go` 绑定草稿与不可变追加计划。检测、播放及终章消费者属于同一原生表的入口，一起更新；共享地址的其他独立表保持原引用。会话通过 `game/quote_sources.go` 提供文本验证与资源保护；没有通用元数据框架。声明的脚本首部只提供最小保护范围，不建立全局脚本执行图。

会话级资源声明由 `game/claims.go` 按 stamp 缓存汇总，并核对传入字节确实对应缓存输入；旧快照或预演字节不会发布为当前修订的缓存。声明涵盖记录表、文本、图像根、商店、支援、地形、斗技场与章节事件资源。章节头、条件表及引用载荷以原生位置为所有者身份，共享同一事件头的章节产生相同声明。条件表本体、脚本代码、地点载荷和部署组分开声明；开场、条件和结尾扫描确认的指令使用独立的 `event.ScriptCodeOwner`，允许共享入口及内部入口编辑同一段代码。指针站点（条件操作数、开头／结尾、调用和部署组）保留独立所有者；指令内的调用及部署操作数以脚本代码为宿主。脚本参数修改按整段范围检查会话的全部 Claim，只写发生变化的指令；写入判定遵循[资源声明约束](#人工审查的设计约束)。

`maps.TilesetDraft` 拥有一份已有图块配置的组成与地形字节，`TilesetPlan` 冻结变化、共享章节和一次追加写入。它通过当前章节的配置入口发现共享处，对改变的图块引用逐章验证；独立入口和旧载荷保持原样。`tilesetResources` 只解析图像、调色板和配置，地图布局作为独立预览读取，损坏布局不阻止有效配置编辑。两份图像按原生加载槽组合并记录实际可用编号，不把未加载间隙解释为空白。`TilesetConfig` 捕获一份不可变的原始文件快照，导出包含有效手动修改，导入返回与原手动草稿分离的整份配置替换；保持当前长度与未解释区。`pages/chapters` 在独立的图块定义标签管理按章节及定义保留的输入、选择和审核状态；导入审核单独持有草稿，取消恢复原输入，应用后重读。文件回传检查 stamp、条目身份和导航代次；与布局绘制草稿分别应用，按同一修订与布局 stamp 失效。

`maps.Palette` 捕获原生 320 字节色表及独立的可选预览资源，提供不可变 PNG 输入；`PaletteDraft` 只改变显式配色范围，`PalettePlan` 拥有颜色变化、共享用途及一次追加提交。地图读取与 Claims 使用同一个原生长度，背景渲染只访问实际提供的配色组。`pages/chapters` 按章节及常规／迷雾／完整范围保留文件草稿，`pages/records` 与工作区连接窗口文件操作；页面重置保留动作连接。`internal/app/resource_png.go` 在后台解码不可变资源，通过 `Window.Update` 返回结果；页面核对来源 stamp 和当前入口身份，错误或迟到回调不发布新草稿。PNG 编解码与系统对话框分别留在领域和 app，领域包不依赖 MyGo。`internal/app/tileset_config.go` 承接配置文件的后台读取与回传；`resource_file.go` 为 PNG 和配置文件共用有界读取、导出路径检查及已打开 ROM 的覆盖保护，已有 PNG 错误码保留。

`maps.Graphics` 捕获已有图像流、两种原生加载消费者及可选预览资源。`GraphicsSlot` 区分第一份／第二份加载位置；所有者身份由图像资源类型及具体 PLIST 站点决定，同一入口的两种消费者共享所有者，其他资源类型保持独立。`graphicsInputs` 独立读取两份流，`combineMapGraphics` 按编号 0／512 组合并记录实际加载区，替换按站点匹配，保留独立入口的后加载覆盖。`GraphicsImport` 显式选择联合配色与目标组；`GraphicsDraft` 在后台完成索引 PNG 解码、像素打包、压缩及可选单组颜色替换。`GraphicsPlan` 检查所有共享加载位置容量，分别汇总图像与配色用途，在同一个构建器追加变化资源并重定向各自入口，一次应用或撤销；只变像素／颜色时保留另一资源的原指针。配色转换、变化色槽及共享发现与独立配色流程共用私有实现。`pages/chapters` 按章节和加载位置保存草稿，通过文档 stamp、条目身份和导航代次拒绝迟到回调；应用、取消或重读后刷新当前流并恢复文件入口焦点。文件面板仍由 app 承接，领域不访问窗口。

`event.Layout` 选择条件记录、地点命令及不可变指令集。指令集分别组合 FE6、FE7J/U、FE8 的编码定义，运行时不再按版本身份分派。字段宽度、条件步长、间接操作数范围由布局表达；字长表和长度前缀各有解码实现。已知指令的编辑字段同时提供资源发现信息，未开放编辑的指令仍保留已确认长度及控制流规则；槽状态追踪与坐标回退作为明确能力保留。

记录负责选择头像引用、职业回退和通用小头像编号，头像编辑器消费该选择并解释原生资源。文本及图像替换消费记录提供的使用处、手动区域和保护信息；它们不从 UI 标签或显示名称推断规则。

`space.Builder` 在同一只读快照上组合追加、资源替换、搬迁、引用重定向和原地覆盖。`AppendEncoded`／`ReplaceEncoded` 在确定位置后调用领域编码器，将地址计算与载荷加入合为一项操作。`space.PointerSite` 显式携带站点、所有者及 `ExpectedWord` 完整指针字；`Repoint` 接受文件偏移，`ClearPointer` 单独表示清零。`space.Protection` 接入领域的指针／区间保护规则，缺少对应检查时拒绝已有字节写入。每项操作先核对引用、保护规则、边界及与已有计划的交叠，再一起加入载荷、指针与新长度；失败不占用空间，也不改变已累积的操作。`Builder.Plan()` 返回独立的 `space.WritePlan`，包含分配范围和 `rom.Edit`，尚未绑定文档。`edit.NewCommit` 将字节写入与原始 stamp、历史标签一起冻结为 `edit.Commit`；其 `Apply` 校验文档、修订和解析设置，并交给 `rom.Document.ApplyEdit` 一次提交。领域预览中的 `Plan` 持有这个待提交操作及自身的影响信息。事件参数与世界地图路线的原地修改也在构建器中组合；领域层仍负责完整宿主范围的保护、编码及引用选择。

空间管理默认末尾追加，也接受带来源的明确可用区间。已有表搬迁通过 `Builder.Relocate` 处理源范围及内部偏移引用，共享构建器的分配与交叠检查；外部引用检查所属者，复用已有区间还执行区间保护。搬迁源区在同一构建器内保持不可写。资源替换保留原载荷，未选定的独立引用继续使用旧资源。保留未知字节不等于可以自动搬迁未知结构。写入机制见[ROM 与空间参考](reference/rom-editing.md)，包级设计和调用示例见 `space/doc.go`。

保存基于一致快照，在同目录写临时文件后替换目标并保留备份。磁盘 I/O 不持有状态锁，保存点对应写出的快照，期间新修改仍保持未保存。外部修改在保存和窗口聚焦时检测。

错误由发现问题的包定义 `fault.Code`，跨包操作补充上下文并保留原因。错误码 ID 保持稳定；调用方不解析 `Error()` 文本。规则见[错误设计](error-design.md)。

## 界面与线程

`app` 通过 `pages` 组合界面，不直接依赖组件。`pages/workspace.go` 负责标签导航、窗口缩放和窗口动作，各页面保留自己的筛选、选择与草稿。页面主区以 `Grow(1)` 分配顶部与底栏之间的剩余高度，嵌套标签下的内容同样占剩余空间；滚动容器在该边界内处理内容增长，不以父容器全高再叠加相邻栏。窗口缩放通过 `Context.SetZoom` 作用于布局和输入坐标；`mapview` 仍只按自己的地图倍率换算格子，不再次乘窗口倍率。共享 `components.Sidebar` 分开保存用户首选宽度和当前显示宽度，在逻辑窗口变窄时为编辑区留出空间。

五版世界地图事件入口与指令由 `event` 持有，FE6 使用 `WorldMapEventsFormat.ChapterPLIST` 按有效章节布局解析，FE7／FE8 使用独立目录声明；`Source.WorldMap` 只读取节点、路线和轨迹以校验改变的引用；版本根指针留在会话组合层。`WorldMapClaims` 在章节表之外声明目录、脚本及调用的资源范围，章节和独立目录共用有界脚本索引。关联章节不作为世界地图脚本的战场上下文。FE6 的混合资源表只按明确章节引用发现脚本，索引 0 按实际指针解释；普通事件头错误不遮蔽已确认的世界地图入口。`maps.Format.Claims` 声明各类地图根、入口和已确认载荷，会话统一检查与脚本的交叉写入。地图写入传递实际资源所有者；世界地图 PLIST 根只在事件格式声明，章节协调层把它作为地图编辑的外部消费者传入。

`pages/records` 同包内的 `form` 实现字段表单、人物／职业详情及素材引用。记录页提供通用表导航，章节详情由 `pages/chapters.Page` 组合底图、部署、条件、路径及变化表编辑；现有章节标签和导航流程保留。独立文本、头像、脚本、商店及战斗对话页通过回调跳转，不导入记录页私有实现。`Workspace` 按人物持有死亡对话页实例，通过渲染回调嵌入人物详情，分别保存人物／表草稿并按修订失效；文本使用处由组合层返回对应人物标签。共享 `components.Thumbnails` 消费头像和 `sprite` 领域预览，缓存可重用的 Bitmap 及来源 stamp，不保存构建期元素。`pages/shops` 的章节库存仍交给事件计划提交，准备、默认和节点库存交给商店编辑器提交；不同页面草稿互相通过文档修订失效。`pages/worldmaps` 在据点／路线标签按记录保留输入与预览；地名、章节、后继节点和商店通过组合回调导航，商店可返回所属节点。节点可筛选相连路线，端点和地图标记可返回节点；页面私有的路线画布消费领域图像与坐标，只显示控制点顺序，不模拟原生样条。字段组与控制点使用稳定身份，重排和提示的出现不重置输入焦点。道路画布仅累积未完成手势和缓存位图，松开后将一笔交给领域草稿；工作区通过 `editor.State.DraftHistory` 路由撤销，忙碌或失效时取消手势并禁止回退到文档历史。据点／路线详情的引用展开区消费 `event` 的有界查询结果，完整目录由脚本页浏览；脚本页与节点／路线页经 `Workspace` 回调互相导航，分别保留草稿，不互相导入私有实现。

`pages/quotes` 的独立战斗面板和嵌入人物详情的死亡表单复用字段、文本阅读和计划操作；FE8 筛选消费 `quote.BattleCondition`，保持共表草稿，正文阅读消费 `text.Value.Plain`。页面按原生表持有独立草稿，用稳定记录 ID 保存输入和排序后的选择；无效输入阻止预览，文档或布局变化使旧计划失效。人物、章节和文本链接通过页面组合回调导航；文本使用处包含对话表并可返回对应记录。脚本引用只关联地址和原始字节，不从页面选择推断章节上下文。

`components` 保存窗口外观和通用控件；`typography.go` 集中维护以正文为基准的字号层级，`ApplyTheme` 设置默认正文字号，普通文字与控件继承主题，标题和辅助文字引用语义字号。`AssetEditor` 复用 PNG 流程。`textreference.go` 统一文本引用的选择、跳转和完整正文阅读；选择状态保留到控件通知处理后，并跟随外部 ID 变化，文本索引继续由领域编辑器按文档、修订和布局缓存。页面仍负责引用写入与计划失效；只读的脚本关联文本选择不产生写入。`components/shopview` 共享货物列表、道具选择和第二字节输入，接收所属草稿的可编辑状态及预览失效回调，不负责入口写入；来源标题消费类型化引用。`components/mapview` 接收地图预览、读取错误和交互回调，只维护位图、缩放、坐标、选择与手势；它不持有 `Session` 或读取 ROM。章节页面缓存领域预览，检查文档、修订和布局后再复用；尺寸变化清理选择和未完成手势。

撤销命令由 `editor.State.History` 选择。每次构建先清空焦点与草稿目标，可见地图编辑区按稳定 Handle 的焦点注册可用回调；回调只持有领域草稿与页面数据，不保存 Context 或 Element。空的草稿目标仍占有撤销，过期校验在执行时再次进行；控件因过期被禁用而失去焦点时，保留当前草稿目标，直到焦点进入其他区域。菜单和根快捷键都调用同一状态入口，菜单按文本／草稿／ROM 目标及可用操作更新。macOS 使用应用级系统菜单并跟随焦点窗口；Linux／Windows 使用系统标题栏和常驻窗口菜单，每个窗口的菜单状态独立取自所属工作区。打开、保存与另存为的可用状态随忙碌状态和会话变化更新。视图构建触发的菜单状态变化经 `Window.Update` 延后刷新，避免在 GTK 绘制期间替换原生菜单控件。原生对话框的输入仍由系统处理，忙碌期间阻止文档与领域草稿操作。

```mermaid
flowchart TD
    Command[菜单与快捷键] --> Text{输入草稿拥有焦点?}
    Text -- 是 --> Native[MyGo 文本历史]
    Text -- 否 --> Draft{地图编辑区域拥有命令目标?}
    Draft -- 是 --> Local[草稿历史：为空或过期时禁用]
    Draft -- 否 --> Document[ROM 文档历史]
```

纯数值和地址解析位于 `internal/input`。窗口状态及异步结果遵循 [AGENTS 的线程约束](../AGENTS.md#实现边界)，验证方法见其[命令与验证](../AGENTS.md#命令与验证)。

## 应用诊断

`internal/applog` 中的 `Sink` 是日志运行期句柄，持有组合后的 `slog.Logger`、可用日志目录和 `RingBuffer`（固定容量的近期记录缓冲）。`app.Run` 安装默认 logger，退出时先等待开发路径记录完成，再记录致命错误并关闭日志文件；`main.go` 据返回值设置非零退出码。标准错误流使用文本格式，轮转文件使用 JSONL；文件初始化或写入失败时，警告直接进入标准错误流与内存，避免再次经过失败的文件处理器。配置与保留策略见[开发说明](development.md#日志与诊断)。

领域核心只返回结果与 `fault.Error`。窗口错误通过 `editor.State.SetErr` 更新横幅；保留局部草稿错误的页面通过 `State.Report` 记录诊断，不改变提示位置。两者按错误码和诊断文本去重。`State.Edit` 包围同步领域提交，只在成功且文档修订变化时记录 `apply`；文档撤销重做使用同一状态入口记录 `undo`／`redo`。草稿历史和空写入不产生文档历史事件。

文件操作的错误在 `Window.Update` 回传中带显式顶层操作名记录，再交给页面，因此同一错误不会同时以应用和编辑器操作重复输出。打开、保存、重载与模拟器启动记录成功上下文；外部修改只在窗口状态从未变更转为已变更时记录。错误分类与字段见[错误设计](error-design.md#日志采集)。日志接收器可并发使用，`editor.State` 仍只在 UI 线程修改。

## 未决问题

`records.Rule` 的 Stride／Count／Probe 与 `quote.Rule` 的终止规则仍以字面量留在 `game/feXX.go`；尚未决定是否将这些结构参数提取为领域命名布局，仅在版本文件保留地址与布局选择。这是[版本事实约束](#人工审查的设计约束)的既有例外，不是新增版本分派的许可。

当新增或修改表结构导致多个版本重复维护同一组参数，或需要独立组合、验证结构规则时，在该功能的设计审查中决定是否拆分，并同步更新本节。仅增加 FE7J 的表指针时，把地址放在 `game/fe7j.go` 并复用适用布局，不触发通用框架重构。

## 后续领域的接入

成长与其他移动规则应按自身数据和操作建立边界；记录保存关联 ID 或指针，不接管被引用内容。世界地图、动画和音频分别拥有原生资源解析与编码，章节或具体操作组合它们的共享影响。

补丁、诊断与重打包根据可确认的结构生成完整编辑计划，复用文档历史和空间规划。外部工具、CLI 与运行时调试通过领域结果和系统适配器接入，不把文件对话框、进程生命周期或平台逻辑加入领域包。新增能力按具体需求提取定义，功能状态仍只维护在覆盖矩阵。

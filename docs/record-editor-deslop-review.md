# 人物／职业设计的 kill-ai-slop 审查

状态：用户已批准 A、B、C 全部应用，并要求实现设计。三组修改已在实际人物／职业页面落地；后续又按用户反馈将 PNG 操作移入独立头像表、把武器等级选择集中到当前字段检查器。下表保留的是修改前的审查记录，实际结果见文末。

## 结论

没有确认需要清理的渐变、装饰图标、玻璃效果、胶囊标签或多层卡片。需要收紧的是默认信息量、数据层级和重复过程说明，归为三组、八个修改点。

建议先减少重复派生行，再调整间距和灰阶，保留能力列、精确熟练度、四字节特性及版本语义。

## 扫描与核对方法

- 原始扫描器对设计文档和原型文本副本运行，核心规则命中 0 项。
- 扫描器不收录 `.go` 扩展，因此把临时原型按原行号复制为 `.mjs` 文本供正则扫描，没有转换或执行这份副本。
- 增加 MyGo 层级、默认展开和中文过程说明的候选规则，产生 10 个候选。逐项读取原文件，并核对人物、职业、关联数据和 880 像素预览后，确认 8 项需要修改，另 2 项有意保留。
- 自定义规则仅索引待核对位置；默认展开是否过量、灰阶是否承担了过多层级，均由视觉与任务判断，不作为自动 lint 结论。
- 扫描及原图备份保存在 `/tmp/febuilder-record-deslop.4z7n9X/`，原型为 `/tmp/febuilder-record-design.mt5TY1/preview.go`。

## 明确保留

- [文档开头的提案状态](/tmp/febuilder-record-deslop.4z7n9X/source/record-editor-design.md:3)与[原型底部的一处预览标记](/tmp/febuilder-record-design.mt5TY1/preview.go:72)：两者分别说明文档和截图的状态。这是 10 个候选中有意保留的 2 项。
- `#C44B2C` 强调色、白色主区域、系统字体：已有项目选择，适合原生数据编辑器。
- 头像与职业像素图：实际编辑对象，帮助辨认记录。
- 记录 ID、版本、ROM 地址和特性字节：真实标识与编码，不是装饰性编号或终端风格。
- 四组特性复选框：对应四个原生字节，分组有编码依据。
- 能力与武器矩阵：存在明确的比较和编辑任务，不按营销卡片或虚构统计处理。
- 估算限制、人物熟练度 0 的继承语义、未知位说明：与编辑判断直接相关。

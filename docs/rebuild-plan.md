# FEBuilderGBA 原生 Go 重建计划

状态：设计基线已确认。旧版来源索引、原生能力原型和 FE8U 基础编辑闭环已落地；FE8J／FE6 日文原版基础适配也已完成文件及 UI 验收，章节效果独立待验收。完整语义盘点、其余桌面交互、可变长写入和后续版本仍在推进。实际进展见 [实现与验证记录](implementation-status.md) 和 [覆盖矩阵](coverage.md)。

## 已确认的目标

| 项目 | 决策 |
| --- | --- |
| 覆盖基线 | 当前 `FEBuilderGBA/` 子模块提交 `8e355791` 的功能，建立逐项覆盖清单；后续上游新增功能另行安排。 |
| 最终范围 | 完整覆盖旧版能力，覆盖 FE6、FE7J/U、FE8J/U，以及原有导入导出、补丁、诊断、重建、工具集成等工作流。 |
| 实现 | 编辑器及内置领域能力用 Go 重建，界面使用 MyGo 原生 `ui`。独立的原生模拟器、汇编器、编译器可以作为外部工具。旧 Windows/.NET 实现作为参考，不作为新版运行前提。 |
| 平台 | 首阶段以 macOS 验收；核心与平台无关。Windows、Linux 后续分别验证。 |
| 文档模型 | 直接打开、编辑和保存 ROM。工程目录与“资源构建 ROM”不作为主要模型。 |
| 编辑与保存 | 有效修改进入内存文档，Cmd+S 保存，支持另存为、统一撤销重做、完整操作回滚和保存前备份。磁盘外部变更需明确处理。 |
| 写入判定 | 根据版本、已知补丁和表指针提供编辑；未命中补丁名单本身不限制编辑。具体检查发现非法地址、无效长度、明确布局冲突或无法确定写入位置时，停止该次自动写入。保留显式指定地址/布局及原始字节编辑，统一检查边界和记录撤销。 |
| 兼容 | 兼容旧版对外文件格式、社区资源，以及旧版支持的已有改版 ROM。新版内部实现可以重设计。 |
| 扩展 | 面向后续游戏版本和补丁规则的内部扩展边界；不要求动态代码插件。 |
| 交互 | 全面重设计。一个窗口对应一个 ROM，允许多个独立窗口；窗内编辑标签页共享同一文档和撤销历史，按需显示属性、引用、错误及历史面板。保留地址、指针、原始数据等高级操作。 |
| 首个功能版本 | 先贯通 FE8U 的人物、职业、道具编辑及实际保存验证，随后继续完整覆盖。 |
| 语言 | 简体中文、英文。界面语言与游戏文本编码分别处理。 |

领域核心能够脱离 UI 运行，以支持场景验证。旧版已有命令行能力进入覆盖盘点，新增命令行产品能力另行安排。

- [人物编辑](../FEBuilderGBA/FEBuilderGBA/UnitForm.cs)：依赖文本读取，并识别技能系统和魔力拆分等补丁。
- [FE8U](../FEBuilderGBA/FEBuilderGBA/ROMFE8U.cs)、[FE6](../FEBuilderGBA/FEBuilderGBA/ROMFE6JP.cs)：存在表尺寸、指针定位、文本和章节布局差异；部分表会搬迁，不能全部按原版固定地址处理。
- [补丁加载](../FEBuilderGBA/FEBuilderGBA/PatchForm.cs)、[事件汇编](../FEBuilderGBA/FEBuilderGBA/EventAssemblerForm.cs)：需要兼容旧补丁定义，并为外部工具提供原生接入方式。
- [重建导出](../FEBuilderGBA/FEBuilderGBA/ToolROMRebuildMake.cs)、[重建应用](../FEBuilderGBA/FEBuilderGBA/ToolROMRebuildApply.cs)：结构化重排涉及未知二进制数据、指针和空间分配，不能仅靠重新编码已知字段实现。
- [外部修改监视](../FEBuilderGBA/FEBuilderGBA/ROMUpdateWatcher.cs)、[RAM](../FEBuilderGBA/FEBuilderGBA/RAM.cs)：文件外部变更和模拟器内存访问需要重新设计平台边界。仓库中的 GDB 实现不能直接视为已验证的 macOS 调试方案。

这些检查用于确定依赖和风险。阶段 0 已生成 [旧版来源索引](legacy-inventory.csv)，完整行为清单及验收状态继续在 [覆盖矩阵](coverage.md) 中拆分和维护。

## 架构方向

以下边界落实已确认的编辑、保存、兼容与扩展要求。具体包名、接口方法和数据表示随实际用例收敛，后续版本适配应持续检验这些边界。

```mermaid
flowchart TD
    UI["MyGo 原生工作区"] --> USE["编辑操作与查询"]
    USE --> DOC["ROM 文档：字节、修订、撤销"]
    USE --> GAME["游戏适配：布局、编码、能力"]
    GAME --> PATCH["补丁识别与规则"]
    USE --> CODEC["文本、图像、事件、音频编解码"]
    USE --> SPACE["空间分配与引用更新"]
    DOC --> FILE["文件保存、备份、外部修改检测"]
    USE --> TOOLS["外部工具适配"]
```

- **ROM 文档**表示一次打开的 ROM 及其编辑状态。每个文档拥有自己的字节、版本识别结果、撤销历史和保存基点，不依赖全局的“当前 ROM”。解析缓存从字节及修订状态派生。
- **编辑操作**表示用户的一次完整改动，例如批量修改道具、导入头像或安装补丁。操作涉及多处字节、长度和指针时，需要一起成功或一起撤销。UI 不直接获得可随意修改的底层字节切片。
- **游戏适配**描述版本识别、字段布局、指针解析、文本编码和能力差异。普通布局使用数据描述；复杂编码和行为使用 Go。FE8U 首个闭环之后，尽早用 FE8J 和 FE6 检验边界。
- **元数据层**统一表达游戏格式与规则定义，方向见 [游戏元数据层设计](metadata-design.md)。设计已确认，当前暂缓实施；等版本扩展、事件或补丁等具体功能需要时再接入，不作为当前工作的前置重构。
- **补丁规则**描述已知改动的检测条件及其对布局、字段和能力的影响。检测、解释和安装分开；相关编辑器按识别到的规则调整字段和布局，并检查本次写入条件。未匹配补丁规则本身不阻止编辑。
- **空间与引用管理**负责有依据的可用区间、对齐、扩容、共享资源和引用更新。原始字节恰好像指针、或一片字节为 `00`/`FF`，都不能单独证明可以移动或复用该区域。
- **文件与工具适配**负责平台行为。外部工具在隔离副本上执行，结果经过差异与结构检查后作为一个编辑操作导入；失败不得留下半次修改。
- **i18n**使用稳定消息标识和参数化文本，UI 与诊断分别提供中英文。新版 UI 按自己的交互设计编写文案，不迁移旧编辑器的界面翻译，也不要求文案逐项对应。资源 ID、字段定义、格式协议和 ROM 输出不受界面语言影响；游戏规则说明及社区资源自带的多语言元信息与编辑器界面文案分别处理。

优先使用 Go 标准库和已经选定的 MyGo。新增依赖需有具体能力需求，不因预设架构引入通用插件框架、脚本引擎或大型状态管理层。内部接口在验证期间可以调整；已发布的文件契约和社区格式需要明确兼容策略。

## 阶段与验收

阶段表示主依赖顺序。每个阶段都交付可使用的完整操作，并持续扩展覆盖清单。各阶段的游戏列不能留到末尾才填充：新增功能应同步列出各版本的已实现、未实现与确实不适用项。

| 阶段 | 工作内容 | 完成证据 |
| --- | --- | --- |
| 0：覆盖盘点与原生交互验证 | 固定基线；枚举菜单、表单、命令行、格式、配置数据和外部工具；建立功能矩阵。验证 MyGo 的密集表格、键盘编辑、中文输入法、像素图像缩放/坐标拾取、长文本、原生文件对话框。 | 能追踪旧版入口到任务及验收场景；交互样例在 macOS 实际运行；框架缺口有复现和处理路线。文档中存在组件不等于已经通过运行验证。 |

| 4：章节、地图与事件 | 章节配置、地图绘制、地形、地图变化、事件单位、AI、商店、支援、事件脚本和世界地图等内容。 | 完成一个包含地图、单位和事件变化的章节修改，保存后运行验证；错误可以定位到资源与字段；共享资源和引用关系可追踪。 |

| 6：动态图像与音频 | 战斗/地图动画、魔法效果、OAM 等动态图像格式；歌曲、音色、MIDI/WAV 导入、播放和音频资源管理。 | 代表性社区素材往返和实际运行验证；大小、压缩、引用与时序行为可解释；独立工具依赖可在 macOS 使用。 |
| 7：诊断、修复、重建与高级调试 | FELint、引用查询、差异/合并、备份恢复、问题报告、ROM 重排、十六进制与反汇编高级能力；模拟器内存/调试与相关工具。基本诊断和原始数据查看在前序阶段按需要提前交付。 | 正常、损坏及改版案例均有验收；未知内容不会被静默丢弃；重排通过引用检查和运行验证；平台特有旧行为有明确等价方案。 |
| 8：覆盖收口与发布 | 补齐功能矩阵全部叶项、原有配置和附属文件兼容、已承诺格式与命令行能力；macOS 分发及更新、可访问性、长时间编辑和性能；整理 Windows/Linux 差异与验收计划。 | 每项有验证证据；未完成项明确列出，不能以“主要功能可用”宣布完整覆盖。macOS 交付完成不等同于三平台全部通过验证。 |

关键顺序约束：

1. 补丁识别从阶段 1 开始；补丁管理界面主要在阶段 5 交付。
2. 撤销、文件一致性和修改范围从首个写入操作开始建立，后续所有导入和工具都复用。
3. 版本扩展在阶段 2 检验，避免先完成全部 FE8U 再抽象。
4. 文本写入、图像导入、地图扩容和补丁安装都依赖空间及引用管理；它们可以分别提供固定长度的早期能力，但不能绕过共同写入机制。
5. 实时模拟器调试独立于最初的“启动模拟器试运行”；后者进入阶段 1，前者需要单独验证协议和平台可行性。
6. 高级 ROM 重排保留为完整覆盖目标；普通打开和保存不自动重排 ROM。

## 功能矩阵与任务拆分方式

阶段 0 建立逐项矩阵，每条至少包含：

| 字段 | 用途 |
| --- | --- |
| 稳定功能 ID、旧版入口和来源 | 防止漏项，并支持回到旧实现核实行为。 |
| 游戏版本与补丁前提 | 区分通用能力、版本差异与具体改版规则。 |
| 对外格式及附属文件 | 记录社区兼容契约，包括注释、符号等非 ROM 数据。 |
| 新版入口和领域操作 | 保持新交互与旧能力可对应，允许多个旧窗口合并。 |
| 前置能力 | 标明文本、压缩、空间、工具或其他编辑器依赖。 |
| 代表性输入、预期输出和验证方法 | 把“有界面”与“能完成任务”区分开。 |
| 状态及已知差异 | 尚未盘点、待实现、实现中、待验证、已验证；不适用必须给出理由。 |

任务以可验证的用户操作拆分，例如“导入一个头像并保存后重新读取”，而不是仅以“添加某个工具函数”作为交付。每完成一个操作，同步记录适配版本、格式兼容、失败行为和验证证据。

阶段 1 的建议实施顺序：

1. 定义 ROM 文档和完整编辑操作，建立打开、无修改保存及保存失败的场景验证。
2. 接入 FE8U 识别、表指针定位与文本只读解码，形成真实可浏览的数据列表。
3. 实现人物、职业、道具的字段定义和基础编辑；覆盖名称、数值、位标志和关联跳转。
4. 将所有编辑接入统一撤销、保存基点和脏状态；加入批量操作、非法值定位与外部文件变化处理。
5. 接入 MyGo 工作区、中英文资源与键盘操作，完成原生交互验证。
6. 通过真实 ROM 保存重开、旧版对照和模拟器试运行验收，再进入第二个游戏适配。

## 验证原则与当前缺口

- 不保留单元测试、`_test.go` 文件或测试专用样本生成器。以本地真实 ROM 的临时副本完成文件、UI 和模拟器操作验收，结合构建、静态分析及结果记录；不把同一套测试改名为其他入口继续保留。
- 无修改打开/保存必须保持完整文件字节一致。固定字段修改检查准确的字节范围，撤销应恢复全部字节、文件长度、引用和保存状态。
- 变长或压缩资源同时检查解码后的内容、引用完整性和实际使用行为。只有在编码结果本身属于兼容契约时才要求与旧版逐字节相同。
- 一次批量修改、导入或补丁操作在中途失败时，文档不应留下部分结果；保存失败不应破坏原文件或误标为已保存。
- 使用旧版读取结果、独立的格式预期和模拟器行为相互核对。旧版缺陷不自动成为新规范；差异必须记录。
- 每个游戏与重要改版布局维护代表性语料，包括表搬迁、已扩容、补丁组合和损坏输入。真实 ROM 本地配置使用；没有对应语料时，该兼容项只能标记为待验证。
- 本地语料位于 `febuildergba-go/.rom/`，目前包含《Vision Quest v3》和《Dream of Five》两个扩容 FE8U 改版；目录不进入 Git。两份副本已完成精确字段修改、保存重开和高级编辑检查，并经 mGBA 确认修改后的 ROM 读取及启动活动。自定义字库、章节内属性效果、其他游戏版本及外部格式仍需扩展验收，详见 [实现记录](implementation-status.md)。
- 性能用真实数据集测量列表滚动、像素画布、文本输入、打开、保存及大型导入；阶段 0 建立测量方式，不预先编造没有测量依据的性能数字。

## 编辑行为

### 编辑与保存

字段有效修改立即进入内存文档；普通字段不再多一次“写入 ROM”按钮。Cmd+S 明确保存到磁盘，提供另存为；批量修改和资源导入作为一个完整撤销操作。保存采用同目录临时文件及替换策略，并保留可恢复的旧版本。磁盘文件被外部修改时提示重新载入或另存，避免静默覆盖。

输入法组合文本、尚未完成或非法的输入仍属于控件草稿，不能作为有效字段变更提交。长任务基于明确的文档修订执行，完成时检查结果是否仍适用于当前修订。

### 改版识别与写入判定

当前基线的实现依据：

- `ROM.LoadLow` 按 ROM 标头和最小长度选择游戏实现，另有 `LoadForceVersion`；这不是对整个改版布局的认证。
- `PatchUtil.SearchSkillSystemLow` 和 `MagicSplitUtil.SearchMagicSplitLow` 通过已知字节特征识别补丁。没有匹配时返回 `NO`，未单独返回“未知补丁”状态。
- `UnitForm_Load` 根据识别结果显示技能入口和魔力拆分字段，属于局部能力适配。
- `U.FindROMPointer` 在候选指针中查找，有的重载额外检查结构；检查失败会逐级回退，最终可能返回第一个候选。
- `InputFormRef.WriteHandler` 检查受保护地址、表范围、ID 0 和对齐。部分检查支持配置成直接允许、询问或拒绝；其范围检查在原始边界不明时也存在放行路径。这些检查不等于对结构化布局正确性的保证。

在检查的核心路径中，没有发现统一的“已识别改版可编辑、未知改版只读”分类，也不能假定可以可靠发现所有未知改动。

新版沿用游戏版本规则、已知补丁识别和通用表编辑，不以“未命中补丁名单”作为只读条件。仅在具体检查发现非法地址、无效长度、明确的布局冲突或无法确定本次写入位置时，停止该次自动结构化写入并给出原因；高级用户可以显式指定布局/地址后重新检查，或使用原始字节编辑。原始修改也经过边界检查和统一撤销。

保留未知字节不等于能安全搬迁它们；引用不明确时，不自动移动未知结构。无法检测的自定义布局仍需靠实际改版语料验证，不能把静态校验通过视为完整兼容证明。

### 工作区组织

一个窗口对应一个 ROM，允许同时打开多个独立窗口；窗口内以导航、编辑标签页和属性/引用面板组织功能。人物、道具、地图等视图共享同一文档和撤销历史。错误、历史、地址信息按需展开；常用操作支持键盘，避免通过大量模态窗口完成日常编辑。

## 实施起点

已获整体实施确认，当前按阶段 0 → 1 推进：建立可追溯的功能矩阵，验证原生交互，并核实真实 ROM 语料、旧版对照执行和模拟器环境；同时按阶段 1 的操作闭环实现 FE8U 首个功能版本。环境或语料暂缺时继续其他独立任务，对应验收项保持待验证。

后续具体算法、包名和控件细节在该基线内根据实现证据调整；新增产品范围或改变对外契约时再讨论。每次交付同步更新功能矩阵和实际验证证据，直到完整覆盖基线能力。

# macOS 原生对话框与编辑焦点验收

本轮验证了打开／另存面板的显示和取消、关闭确认的保存／放弃／取消、保存失败后的窗口保留，以及原生文本组合与提交。发现并修复了“编辑 → 撤销／重做”始终操作 ROM、忽略文本草稿焦点的问题。

**文件面板中的实际文件选取、保存确认与替换，以及中文输入法候选窗口仍未验收。** 本轮结果不表示全部桌面交互已经通过。

## 输入与执行边界

环境为 macOS `27.0.1`（`26A434`）、Go `go1.27.1 darwin/arm64`、MyGo `v0.6.3`。使用本地真实 ROM 的临时副本：

| 输入 | 字节数 | 原件 SHA-256（前后相同） |
| --- | ---: | --- |
| FE8U 原版 | 16,777,216 | `638cda9d9b72657220fbf7e7a500cd3b64d9686c36e8a56fca69d26d13886f2f` |
| Vision Quest v3 | 28,947,180 | `7ceeadbdf0607fa7b702b73a3657b1ad316c263b06ba245fe699d5404c2935e2` |

验收目录为 `/tmp/fe-desktop-acceptance-a8m3/`。通过临时 Go overlay 启动当前应用及真实窗口，使用 `-race` 构建。临时控制器调用现有应用入口；场景准备使用 `Session.Set`，其余通过 AppKit 窗口事件、原生菜单动作、`NSAlert` 按钮和 `NSTextInputClient` 完成。原生文件面板的取消通过 `cancelOperation:` 执行。截图由窗口自身的 `CapturePage` 生成，控件值通过应用自身的 accessibility 对象读取。

没有替换文件或消息对话框的返回结果，没有合成 ROM，没有在仓库中保留验收驱动、测试入口或新增依赖。初步探查中的面板合成按键未能完成选取／确认，不计为通过。

## 撤销焦点修复

旧菜单直接调用 `Editor.Undo/Redo`。在搜索框提交“中文”后，点击原生“编辑 → 撤销”，搜索文字和筛选结果保持不变；菜单没有调用文本控件自身的撤销。存在 ROM 历史时，该处理路径会操作文档。

当前按编辑上下文选择菜单行为：

- 搜索、批量值、手动表定位、十六进制地址／长度与待写入文本使用原生文本撤销／重做。
- 立即修改 ROM 的数值字段和其他记录视图使用所属窗口的文档历史。
- 原生对话框或没有对应工作区的原生窗口持有焦点时，保留系统文本编辑命令。
- 窗口聚焦或文本编辑上下文改变时刷新菜单。键盘文档快捷键使用相同的文本焦点判断，避免截获草稿的撤销。

`TextDraft` 是标记尚未应用的文本输入的共享组件；每帧重新采集焦点。未改变 ROM 核心或字段写入方式。

| 场景 | 实际结果 |
| --- | --- |
| 文档已有 HP 修改，在搜索框输入 `Eirika` 后点击撤销／重做 | 搜索文字在空值与 `Eirika` 之间切换，ROM HP 和修订不变 |
| 搜索框内 Cmd+Z／Cmd+Shift+Z | 使用文本历史，ROM 不变 |
| 聚焦人物 HP 后点击撤销／重做 | 个人 HP 在 `0／1` 间切换，使用文档历史 |
| 两个原生 ROM 窗口交替聚焦 | FE8U 数值框撤销只改自己的 ROM；Vision Quest 搜索撤销只改自己的搜索文字 |
| 十六进制地址输入撤销／重做 | `00000000／00803D70` 切换，ROM 修订不变 |
| 从 `0x803D70` 读取 1 字节，在待写入框改 `01 → 0A` | 编辑、菜单撤销／重做和 Cmd+Z 只改草稿，未应用时 ROM 修订保持为 `7`，HP 保持 `1` |

批量值和手动表定位已接入同一焦点规则并通过构建与静态检查；本轮未分别重放这两处文本撤销的原生操作。

## 原生组合输入

本机启用的输入源包含 ABC、鼠须管和系统铁木输入法，当前输入源为 `im.rime.inputmethod.Squirrel.Hans`。下面的检查直接调用窗口响应者的 `NSTextInputClient` 协议，验证应用与原生文本接口之间的组合／提交语义，**没有观察到输入法自己的候选窗口**。

| 输入位置／操作 | 实际结果 |
| --- | --- |
| 搜索框设置组合文字“中文” | `hasMarkedText=true`，窗口显示带下划线的组合文字；列表仍保持 255 条 |
| 提交“中文” | `hasMarkedText=false`，列表变为 0 条；ROM 保持干净且修订不变 |
| 个人 HP 原值 `1`，全选后组合 `12` | 组合期间仍为 HP `1`，ROM 修订不变 |
| 提交 `12` | HP 变为 `12`，文档修订只增加一次；文档撤销一次恢复 HP `1` |
| 数值框组合并提交“中文” | 保留非法草稿和范围提示，HP 与 ROM 修订均不变 |

真实输入法候选选择、候选窗口位置、拼音逐键输入及取消组合仍待真实桌面检查。启动仍出现 `IMKCFRunLoopWakeUpReliable` 日志；本轮结果不足以确定其对真实输入法操作的影响。

## 文件面板与关闭确认

| 操作 | 实际结果 |
| --- | --- |
| 打开 ROM | 显示真实 `NSOpenPanel`，父窗口进入忙碌状态 |
| 取消打开 | 面板关闭并解除忙碌；已有文档路径、HP 和脏状态保持 |
| 打开面板存在时请求关闭父窗口 | 关闭被阻止，面板与未保存文档均保留 |
| 另存为 | 显示真实 `NSSavePanel`，取消后路径和修改保持，忙碌解除 |
| 关闭时选择取消 | 真实 `NSAlert` 关闭；原窗口、修改和撤销历史保留 |
| 关闭时选择不保存 | 只关闭对应 ROM 窗口；磁盘副本与原件一致；另一个窗口继续保留 |
| 关闭时选择保存 | 保存成功后关闭对应窗口；重开后读到已保存 HP `1`，文档干净 |
| 文档外部被替换后，关闭时选择保存 | 返回 `rom.external_change`；窗口保留，HP `2`、脏状态和可撤销历史保持，忙碌解除；磁盘外部内容不变 |
| 切换英文后关闭 | 实际按钮为 `Save / Don't save / Cancel`，保存及失败保留行为同上；结束时恢复简体中文 |

成功保存的副本相对 FE8U 原版只有一处差异：

| 偏移 | 原值 | 保存值 |
| --- | ---: | ---: |
| `0x803D70`（人物 `01` 的个人 HP 加值） | 0 | 1 |

保存副本 SHA-256 为 `d1b698612a8e27191f29fd13aa562014b832804f312c6ab57a4e0c2fd97139be`，另保存在临时目录的 `saved-after-close.gba`。前期检查和修复后的保存共生成两份备份，均与原版逐字节相同。Vision Quest 的未保存修改未写入磁盘。随后仅替换临时工作副本来模拟外部修改，没有修改 `.rom/` 中的原件。

## 验证产物与未完成项

临时目录包含 `events.jsonl`（请求、文档状态、原生窗口和控件值）、`history-checks.json`、`hex-checks.json`、`final-results.json`，以及中文组合、非法数值、十六进制草稿和中英文保存失败画面。后者三份 JSON 分别记录 19、4、8 个通过检查点。验收结束后，临时应用进程已退出；运行日志未报告数据竞争。

终端的系统权限预检结果为 `AXIsProcessTrusted=false`、`CGPreflightPostEventAccess=false`、`CGPreflightScreenCaptureAccess=false`。本机文件面板的内容由 `NSRemoteView`／`NSAccessibilityRemoteUIElement` 承载，应用内合成按键没有完成其中的实际文件选择与确认。没有尝试更改系统权限，也没有把直接结束 sheet 或注入返回路径作为选取验收。

当前代码已通过普通／无 CGO 构建、`golangci-lint`、`go vet`、MyGo 生命周期检查，并更新本地签名的 `.app` 和 DMG。根仓库尚无提交，构建日志中的 Git 版本读取失败仍存在，应用构建成功；本轮没有创建提交。临时证据可能被系统清理，ROM、截图和驱动均不进入 Git。

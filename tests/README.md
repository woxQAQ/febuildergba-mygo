# 测试

默认测试放在对应包的 `*_test.go` 中，用例及其验证范围以测试代码为准。合成 ROM 由 [internal/testutil](../internal/testutil) 构造，规则见 [fixtures.md](../testdata/fixtures.md)；需要真实 ROM 的可选检查放在 [integration](integration)，用 build tag 隔离。本文只维护运行方式、测试约束和本地数据准备；新增用例不需要同步登记。

## 运行

在仓库根目录执行：

```sh
# 文档、会话、空间和图像核心
just test-core

# 所有默认测试
just test

# 涉及并发或文档历史时
just test-race

# 可选：使用本地真实 ROM，只修改临时副本
just test-integration
```

## 约束

- 验证实际领域行为、算法和数据结构，不按函数逐一编写单元测试，不复制一套实现来验证产品实现。
- 编解码使用独立构造的固定数据和期望结果，避免仅靠往返测试证明正确。
- 不新增永久 UI 或模拟器测试。界面变更可按需做有界的临时交互复核，领域或文档变更不默认启动 UI 或游戏。文件保存重开与合成 ROM 检查不代表游戏运行正确。
- 修改后运行相关测试及项目检查，通过后结束验证，不无限扩大测试范围。

产品功能的实现状态统一记录在[覆盖矩阵](../docs/coverage.md)，不根据测试数量推算功能覆盖率。

## 证据与停止条件

| 证据               | 能说明什么                                         | 不能推出什么                         |
| ------------------ | -------------------------------------------------- | ------------------------------------ |
| 合成样本与领域测试 | 固定字节、错误边界、未知数据保留、历史和失败原子性 | 全部真实 ROM 或游戏运行正确          |
| 固定真实 ROM 集成  | 已指定版本与样本的读取、编辑、保存重开             | 未采样的改版、自定义引擎或游戏内触发 |
| 临时 UI 复核       | 当次受影响控件的渲染、焦点和操作                   | 后续版本的永久回归保障               |
| 游戏内验证         | 实际执行的版本、章节和场景                         | 未执行的其他场景                     |

真实 ROM 检查由 integration build tag 隔离，命令禁用缓存；缺少本地文件时报告跳过，不能将跳过计为验证通过。样本位置、标头与固定预期见 [fixtures.md](../testdata/fixtures.md)。

代码修改运行相关测试及 `just check`，按修改范围补 race 或真实文件检查；纯文档修改检查 diff 即可。相关检查通过且没有未解决问题后结束验证，不因结果通过再不断扩大样本或启动游戏。临时证据需说明当次范围，不以临时目录链接作为长期依据。

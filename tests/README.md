# 测试

默认测试放在行为所属包的 `*_test.go` 中。领域工作流使用外部测试包（如 `records_test`），通过 `game.Open` 装配真实版本配置，再调用所属编辑器的公开操作；生产包不为测试导出私有配置。

- `game` 根目录验证会话、版本装配和整体错误工作流。
- `records`、`text`、`portrait`、`graphics`、`deployment`、`event`、`maps` 验证各自的编辑行为、错误边界和文档历史。
- `event` 中的商店流程通过章节操作组合 `shop` 草稿；`shop` 验证默认货物、准备及世界地图入口、空指针回退、有效空列表、节点未知字节、独立引用、原生容量和原子历史。
- `worldmap` 验证 FE8J/U 节点和路线的独立固定字节、符号边界、保留位、地名使用处、整条记录冲突及过期计划；路线另含共享轨迹隔离、空指针创建／清空、六点上限、递增进度、连接容量、未知结束字节和 ROM 容量失败。底图及道路用固定颜色验证调色板行距、重复计数、翻转和透明色；道路另以固定流验证重叠与跨行、稀疏编码、透明格与缺省格、笔画历史、空道路、联合提交及共享隔离。动态文件流程按可用节点／路线修改坐标、引用、控制点或道路格子，验证原子历史、其他引用保留与保存重开。
- `sprite` 通过实际会话验证五版待机首帧、停止动画标记、武器图标裁图、透明色与固定像素、修订／布局失效、损坏数据隔离及读取不写 ROM；动态集成按当前职业和可读资源检查缩略图。
- `chapter` 验证章节布局、跨资源引用、脚本与地图关联及尺寸影响。
- `support` 验证五版关系与现有对话的组合写入、反向数值同步、独立共享、空指针初始化、原生消费者、未知字节、冲突与历史；属性加成通过 `bonuses_workflow_test.go` 验证首项匹配、额外 ID、六列写入、尾字节和结束记录、独立输入、冲突与原子历史；真实输入按可编辑能力分别验证关系、对话和加成。
- `arena` 验证五版职业权重与结构操作、固定武器缓冲区、FE8 联机半字、全部消费者、独立及内部共享引用、未知尾部、冲突与失败原子性；动态文件流程按当前可编辑组验证历史和保存重开。
- `terrain` 验证五版移动消耗与加成列、共享天气／职业隔离、部分重叠、未知尾部、冻结计划、手动布局、冲突、容量及原子历史。
- `quote` 验证五版原生战斗／死亡表的顺序、字段、终止记录、已知消费者、独立共享、扩展角色字保留、冲突和失败原子性，以及历史与保存重开；FE8 另验证双方、攻击方／反击方单人及三角攻击条件在同表中的组合创建。
- `text` 的正文摘要检查保留换行、段落、动态替换、未知标记和字面括号，跳过完整头像参数及已知表现指令；原有源文本、写入及历史流程同时验证。

共享样本和临时会话打开见 [internal/testutil 目录](../internal/testutil/)；领域特有的查找与断言 helper 留在所属测试包。样本明确声明输入字节、地址和布局，不从生产私有配置反推输入或预期，固定预期与容易误解的不变量见 [fixtures.md](../testdata/fixtures.md)。

可选集成测试（`tests/integration`）动态发现 `.rom/` 中的输入，不要求固定文件名或特定原版组合。合成测试与集成测试的写入、保存流程均在临时目录执行；验证范围以测试代码为准。

## 运行

按[开发说明](../docs/development.md#环境与命令)准备工具后，在仓库根目录使用 [justfile](../justfile) 中的 `test`、`test-core`、`test-race` 或 `test-integration`。参数与实际包范围由 recipe 维护；检查选择、UI 临时复核及停止条件统一见 [AGENTS](../AGENTS.md#命令与验证)。

导入边界由 `.golangci.yml` 的 depguard 检查，不在 Go 行为测试中重复实现；规则修改的探针要求见 [AGENTS](../AGENTS.md#命令与验证)。

## 集成输入与范围

集成测试扫描 `.rom/` 根目录中的 `.gba` 文件，扩展名不区分大小写。按标头识别版本，再从当前表、资源和脚本中选择可编辑入口。名称、ID、指针、初始数值和图像内容都来自当前输入；重命名文件、只提供某个版本或使用改版 ROM 不需要修改测试清单。

目录为空、标头不受支持、某项资源不可编辑或追加空间不足时，对应样本或流程明确报告跳过；跳过项不计为通过。选定可编辑入口后，意外的计划错误、应用失败、撤销不完整或保存不一致会使测试失败。缺少某类输入不代表该类能力已验证。

集成侧验证无修改保存、字段编辑、搬迁、文本、头像与 PNG、部署、事件条件、章节／默认／准备／世界地图商店货物、世界地图节点、路线控制点与道路、原生战斗／死亡对话表、支援关系、现有支援对话与属性加成、职业移动／地形表及脚本的历史和保存重开流程。固定字节、格式边界和游戏规则的期望保留在合成样本测试中，不从当前实现重新生成预期。

## 测试设计与证据解释

[AGENTS](../AGENTS.md#命令与验证)规定测试对象与验证范围。编解码不能只靠往返测试：编码器与解码器可能共享同一个错误，因此还需对照独立构造的固定字节与手工预期。文件保存重开与合成 ROM 检查也不表示游戏运行正确。

产品功能的实现状态见[覆盖矩阵](../docs/coverage.md)。

## 证据解释

| 证据               | 能说明什么                                         | 不能推出什么                   |
| ------------------ | -------------------------------------------------- | ------------------------------ |
| 合成样本与领域测试 | 固定字节、错误边界、未知数据保留、历史和失败原子性 | 全部真实 ROM 或游戏运行正确    |
| 动态 ROM 集成      | 当前输入中所选可编辑入口的流程与数据一致性         | 未提供的版本、资源或游戏内触发 |
| 临时 UI 复核       | 当次受影响控件的渲染、焦点和操作                   | 后续版本的永久回归保障         |
| 游戏内验证         | 实际执行的版本、章节和场景                         | 未执行的其他场景               |

临时证据只说明当次版本、输入与操作范围，不以临时目录作为长期依据。可追溯入口使用测试代码、固定提交或归档说明；报告要求见 [AGENTS](../AGENTS.md#命令与验证)。
